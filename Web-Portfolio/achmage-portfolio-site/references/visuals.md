# 도식·설명 그림·실제 화면

## 먼저 목적을 결정한다

자료가 어려운 이유가 구성요소의 관계라면 도식, 실제 행동을 상상하기 어려운 경우라면 설명 그림, 결과의 실재를 보여줘야 한다면 화면 캡처를 쓴다. 이미지 수를 채우는 목표는 두지 않는다.

| 종류 | 제작 경로 | 반드시 설명할 것 |
|---|---|---|
| 구조·흐름 도식 | fresh context의 승인된 Pele 중앙 흐름 | 실제 구성요소 이름, 화살표가 옮기는 것, 시작·끝 |
| 설명 그림 | 현재 CMDS Achmage illustration 템플릿 + 지원되는 imagegen | 누가 어떤 기기에서 무슨 파일을 다루는 장면인지 |
| 증거 화면 | 실제 실행 화면 캡처 | 언제 어떤 범위를 확인한 화면인지 |

새 도식은 정확한 renderer/package 핀과 source/render 해시를 남긴다. 외부 SVG를 임의 실행하거나 원격 참조가 있는 SVG를 바로 삽입하지 않는다. 그림은 file/name/device 같은 구체적인 대상과 관계를 보여준다. 구름·빛·뇌 같은 장식으로 실제 동작을 대신하지 않는다.

## 본문에 넣기

그림 앞에서 독자가 살펴볼 대상을 설명한다. 그림 밑 캡션에서 시각 요소와 실제 대상의 대응을 적는다. alt는 캡션을 그대로 복사하지 말고 필요한 시각 정보를 설명한다. 복잡한 도식은 텍스트 설명과 작은 흐름 단위로 나눠 모바일에서도 읽힌다.

템플릿 Figure는 kind, src, width, height, title, alt, caption, source와 선택 sha256을 받는다. 일반 이미지는 HTTPS URL이나 public 아래 경로를 사용한다. 그림 안의 글자도 언어별로 달라야 하면 src를 {ko: 경로, en: 경로}로 지정한다. 이 경우 각 파일의 해시는 별도 제작 기록에 남긴다. 생성 그림을 실제 제품 화면이나 사용 성과처럼 표시하지 않는다.

## 보관과 외부 게시

기본은 프로젝트 public 자산이다. 사용자가 R2/Eagle 보관까지 요청한 작업은 기존 image-publish 흐름으로 업로드하고 공개 바이트 해시를 확인한 뒤 Eagle의 같은 항목을 조회한다. 기존 URL은 그대로 사용하며, 응답이 불명확하면 기존 업로드를 먼저 조회한다.

사이트 제작 요청만으로 별도 계정 연결·반복 예약·공용 이미지 라이브러리 전체 변경을 추가하지 않는다. 도구가 없으면 생성한 척하지 않고 해당 시각자료를 미완료로 남긴다.
