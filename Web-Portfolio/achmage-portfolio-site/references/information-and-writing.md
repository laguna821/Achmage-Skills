# 정보 배치와 쉬운 설명

## 먼저 남길 정보 배치표

프로젝트에 CONTENT-PLAN.md를 만든다. 각 행은 페이지·구획 / 독자의 질문 / 설명할 핵심 / 구체적 예시 / 근거 자료 / 사용할 화면 / 다음 링크다. 자료에 있는 중요한 요구가 어느 행에 들어갔는지 확인한다. 근거가 없는 칸은 추정으로 채우지 말고 빠진 자료로 표시한다.

| 깊이 | 독자가 알고 싶은 것 | 기본 구성 |
|---|---|---|
| 소개 | 무엇이며 왜 필요한가 | 일상적인 문제, 한 문장 답, 실제 사용 흐름 |
| 전체 지도 | 어떤 기능·작품이 있나 | 검색 가능한 모음집과 주제별 읽기 경로 |
| 상세 | 어떻게 만들고 작동하나 | 펼쳐진 소목차, 단계 설명, 구체적 입력과 결과 |
| 근거 | 원문·구현·성과를 볼 수 있나 | 원문 읽기·다운로드, 날짜와 출처 |
| 응용 | 나도 이해하고 따라 해볼 수 있나 | 전체 설명 한 페이지와 Markdown |

랜딩의 구획 순서는 템플릿을 따른다. 프로젝트 내용에 맞게 구획 제목과 모음집의 분류를 고친다. 기능이 없는 작품 포트폴리오는 모음집을 작품으로 이름 붙인다. 명령 입력·기술 사양은 자료가 있을 때만 공개한다.

## 문장

각 설명에서 사람이 유추해야 할 주체와 단계를 지운다.

나쁜 예: “맥락과 실행을 분리하고 결과를 보존한다.”

수정 예: “어제 AI에게 보고서는 다섯 쪽으로 만들자고 말했습니다. 오늘 새 대화를 열면 AI가 그 조건을 모를 수 있습니다. 그래서 프로그램이 어제 정한 조건을 파일에 적어 둡니다. 다음 작업을 시작할 때 그 파일을 읽어 AI에게 알려줍니다.”

문장은 길어도 된다. 다만 같은 말을 반복하거나 정의 없이 용어를 바꾸지 않는다. ‘연결’, ‘하네스’, ‘맥락’ 같은 단어는 그 문장에서 실제로 무슨 파일이나 행동을 뜻하는지 설명한다. 비유를 썼다면 비유 속 물건과 실제 프로그램의 대응도 적는다.

절은 필요에 따라 상황 → 주체와 입력 → 순서 → 결과 → 실패했을 때 → 확인 방법으로 이어진다. 모든 절에 이 여섯 개 제목을 기계적으로 반복할 필요는 없다. 핵심 설명을 접힌 상자 안에 감추지 않는다.

## 근거와 읽기 경로

설계한 것, 코드에 있는 것, 실행해서 확인한 것, 실제 다른 기기에서 확인한 것은 다른 사실이다. 숫자는 출처와 범위를 함께 적는다. 도구 수를 서로 다른 기능 수로 바꾸지 않는다.

원문 제공을 약속한 자료는 전체 텍스트와 읽기·다운로드 링크를 제공한다. 개인정보를 가려야 하면 공개 사본의 변경 범위를 밝힌다. 원문 파일은 고치지 않는다.

한국어·영어는 같은 ID와 구조를 쓰며 뜻을 일치시킨다. 영어에서만 검증 한계나 실패 사례를 빼지 않는다. 직접 링크는 언어를 바꿔도 같은 장·절을 유지한다.

content/portfolio.json은 안내 예시다. 새 프로젝트에서 모든 예시 이름과 사실을 교체하고 sample: false로 바꾼다. sample은 사이트 전체가 가상일 때 쓰는 표시다. 실제 사실과 설명용 예시가 섞인 절은 evidence: {kind: source/example/proposal, note: {ko: 설명, en: 설명}}를 사용하거나 예시가 시작하는 문장에서 분명히 밝힌다. source는 원문에 근거한 설명이라는 뜻이며 실사용 검증 완료를 뜻하지 않는다. build는 사실성을 판단하지 않으므로 실제 공개 전 검수자가 예시 표시와 근거를 확인한다.

원문 text는 원래 언어와 문장을 보존한다. 번역을 추가하면 본문의 별도 절에서 번역임을 밝히고 원문 파일을 덮어쓰지 않는다. 원문 날짜를 모르면 sources.date를 생략한다. updatedAt은 사이트 자료의 갱신일이고 사건 날짜가 아니다. 날짜 없는 변화는 일반 장에서 순서대로 설명할 수 있다.

주제에 맞는 표현이 필요하면 copy.catalogSearch, copy.catalogIntro, copy.catalogCountNote에 한·영 문구를 지정한다. 예를 들어 수업 자료집의 검색은 ‘수업 단계·자료로 검색’으로 쓴다. hero.disclosure에는 실제 진행 순서인지 설명용 시나리오인지 밝힌다.
