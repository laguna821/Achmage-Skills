# 차량 영상의 적대적 시각 검수

검사는 결함을 찾아 수정하기 위한 과정이다. 생성된 원화나 테스트 통과를 광고 품질 보증으로 사용하지 않는다. 자동 검사와 실제 화면 관찰을 기록에서 분리한다.

1. 원화: 앞/뒤/측면의 모델·연식·트림·휠·로고·램프·창문·실내를 공식 자료와 대조한다. 실제 차종의 이름을 달고 다른 차의 특징을 합치지 않는다. 휠 개수, 타이어의 원형, 축 위치, 손과 핸들의 맞물림, 거울 구멍을 확대한다. 판독할 수 없는 특징은 불확실로 남긴다.
2. 합성: 컷 시작·중간·끝, 가장 가까운 시점, 가림 전후 프레임을 뽑는다. 잘린 차체, 이웃 뷰의 잔여 조각, 타이어와 노면의 틈, 그림자 방향, 밝기·색온도 불일치, 창문·미러를 통한 잘못된 풍경을 찾는다.
3. 움직임: 정상 속도와 느린 재생으로 바퀴 축·접점·화면 모서리·전경 가림을 추적한다. 회전하는 사각 패치, 정지한 휠 무늬 위의 이중 회전, 미끄러짐, 카메라가 움직여도 고정된 사진의 관찰각, 컷 사이 다른 휠/차체를 실패로 기록한다. 고정 뷰 2.5D와 실제 3D 촬영을 혼동하지 않는다.
4. 최종 인코딩: 프레임 전체 디코딩, 전환 경계, 검은 화면/깨짐, 작은 모바일 화면의 글자와 주의 문구, 음악/효과음 싱크를 다시 확인한다. 음악은 실제 청취 결과와 신호 측정 결과를 따로 기록한다.

기록마다 `asset_or_cut`, `time`, `defect`, `evidence`, `change`, `recheck`, `status`를 작성한다. 상태는 open / fixed-and-observed / needs-user-review / not-tested다. 원화 디테일과 빛·접지가 open이면 완성 광고나 최종 공개 승인으로 처리하지 않는다. 동일 결함이 다른 컷에 재발했는지도 확인한다.

기술 검사: 절대 시점 재현, 오프라인 자산, 유효한 카메라와 휠 반경, 파일 해시, 캐시 의존, 중단·재개를 점검한다. 접지 좌표가 유한하다는 검사는 화면에서 떠 보이지 않는다는 검사가 아니다. 리뷰 개수나 통과율을 품질 점수로 바꾸지 않는다.
