# 요청 의도와 제작 시작

- ‘모션그래픽 만들어줘’, ‘이 내용을 영상으로 보여줘’는 제작 요청이다. 이미 주어진 독자·매체·길이·브랜드·음악을 유지하고 부족한 핵심만 확인한 뒤 기획 시청본으로 진행한다.
- ‘모션그래픽 발표도 할까’, ‘이걸 움직이는 그래픽으로 설명하면 어떨까’는 활용 상담이다. 내용에서 움직임으로 더 잘 보여줄 대상과 변화, 발표 안에서 사용할 위치와 형식을 먼저 제안한다. 상담을 전체 렌더 지시로 확대하지 않는다.
- ‘발표자료에 모션을 넣어줘’는 승인된 발표 엔진과 함께 사용한다. 발표의 내용·읽기 모드·PDF 대안은 발표 스킬이 담당하고, 시간에 따라 변하는 도해·키네틱 타이포·영상은 이 스킬이 담당한다. 같은 덱 엔진을 두 번 만들지 않는다.
- React 버튼의 hover, CSS 전환, Framer Motion 오류 같은 UI 구현은 해당 개발 도구를 사용한다. 영상 제작과 혼동하지 않는다. 명시적으로 모션그래픽을 원하지 않는 요청에는 제안을 강요하지 않는다.

자동 발견은 스킬을 고려할 근거다. 과거 예제의 승인·개인 취향·음악 시점 보정은 새 프로젝트의 승인으로 복사하지 않는다. 현재 사용자가 허용한 제작·공개 범위를 따른다. 음소거 요청은 세션의 후속 검사에서도 유지한다.
