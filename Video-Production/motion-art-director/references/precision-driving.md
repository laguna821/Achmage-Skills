# 정밀 형상·자유 카메라·동작 음향 — precision-1 시험 경로

`renderer: spatial-three`, `spatial.version: precision-1`을 선택한다. 이 경로는 SVG를 화면에 합성하고 직접 작성한 삼각형 곡면을 Three.js/SwiftShader로 래스터화한다. SVG/Skia만으로 3D를 렌더한다고 설명하지 않는다. 전용 GPU·Blender·이미지 생성 API는 요구하지 않는다. CPU 비용은 순수 SVG보다 높다. 실제 일반 노트북 실측은 별도다.

## 내용에서 형상을 만드는 순서

실제 대상의 식별 특징을 먼저 목록화한다. 차량이면 실루엣·차축·휠 간격·램프·그릴·유리·필러·문 이음새·실내 배치를 서로 다른 작성 대상으로 나눈다. 외부 사진을 그대로 재배포하지 않아도 외관 정확도 비교는 필요하다. 익숙한 로고만 붙인 일반 도형을 특정 모델의 정밀 재현이라고 부르지 않는다.

`lib/precision.mjs`의 `PrecisionBuilder.surface(fn,nu,nv,material)`, `curve`, `rounded`, `mesh`로 장면 데이터를 만든다. 좌표는 미터처럼 일관된 단위를 선택하고 회전은 라디안이다. 각 곡면의 경계·법선·휠 아치와 내부 형상 관통을 앞/뒤/측면/탑뷰에서 확인한다. 처음부터 사진 합성과 동등한 묘사 수준이 된다고 약속하지 않는다.

`spatial.textures`에 직접 작성한 안전한 SVG와 width/height(최대 2048)를 등록한다. `material.texture`로 계기판·지도·워드마크·노면을 붙일 수 있다. 런타임은 이를 로컬 캔버스 텍스처로 변환한다. `<image>`·외부 URL·스크립트는 거부한다. 텍스처 안 글자는 콘텐츠 원문 검사와 별도로 실제 표시 내용을 검토한다.

## 장면 계약

- `scene.spatial.show`: 해당 variant 그룹만 표시한다.
- `scene.spatial.transforms[nodeId]`: position/rotation/scale와 컷 상대 초의 keyframes. 공통 모델을 컷마다 다시 작성하지 않는다.
- `camera.relative_to`: 카메라 위치와 주시점을 해당 노드의 로컬 좌표로 해석한다. `cameraOrbit`는 궤도 키프레임 작성 보조 함수다.
- `spatial.tyre_smoke`: 피사체의 과거 출생 시점 위치에서 연기 스프라이트를 재구성한다. 기본 후륜 위치는 이 시험 구현의 세단 좌표(-/+0.81, 0.13, 1.375)다. **범용 차량별 앵커는 아직 미지원**이므로 다른 모델이면 구현/검증 후 사용한다. 물리 유체 시뮬레이션이 아니다.
- 기존 plates 합성은 precision-1에서 사용하지 않는다. 기존 버전의 프로젝트는 원래 런타임을 유지한다.
- precision-1은 공통 벡터 엔진의 글자 크기 배율·회전·자간·굵기·reveal_rect·동일 위상 경로 morph를 사용한다. 지원하지 않는 blend/clip_path를 구현했다고 주장하지 않는다. 정적 SVG 전체 내보내기나 세로 공간 구도는 이 경로의 검증 범위 밖이다.

## 빠른 컷과 읽기

`editing_contract: shot-rhythm-v1`에서는 컷마다 `shot_role`을 지정한다. `action`은 필수 읽기 문구 없이 최소 8프레임이다. `reading`에는 content_ids별 `reading_windows: [{content_id,start,end}]`가 필요하다. 최소 시간은 max(0.75, 글자 수/10+0.35)초다. 이는 하한 검사이며 실제 글자가 그 시간 동안 보이고 읽히는지는 프레임 검토로 확인한다. 컷마다 모든 문구를 넣느라 주행 리듬을 늦추지 말고, 의미 있는 문구가 읽힐 컷을 따로 설계한다.

## 행동에 연결된 음향

`scene.driving`은 speed/rpm/throttle/slip/pan의 `[컷 상대 초, 값]` 배열이다. 각 곡선은 0초부터 컷 끝까지 덮고 시각이 증가해야 한다. speed는 0–100, rpm 400–9000, throttle/slip 0–1, pan -1–1 범위다. 단위는 연출 계산용이며 실차 성능을 주장하는 숫자가 아니다. sound_gain_db는 -30–6, passby는 접근 중심 시점(선택)이다.

```json
{"speed":[[0,12],[3,24]],"rpm":[[0,2800],[1.7,5700],[1.9,3600],[3,4800]],"throttle":[[0,0.8],[3,1]],"slip":[[0,0],[3,0]],"pan":[[0,-0.7],[3,0.7]],"sound_gain_db":-2,"passby":1.5}
```

속도의 적분은 노면 이동과 바퀴 회전 거리를 정한다. RPM 적분은 엔진 배음의 위상을 정해 변속 시 위상이 끊기지 않게 한다. 스로틀은 음색·크기, slip은 스키드, pan은 좌우 위치를 정한다. 엔진·노면·스키드·지나감 큐는 `drivingCues`가 파생하므로 수동 복사하지 않는다. 이동 궤도를 별도로 작성한 드리프트는 궤도 길이와 speed 적분의 일치도 검사한다. 차량별 실제 녹음이나 정확한 파워트레인 시뮬레이터가 아니다.

외부 음원 편집 시 `audio.mix`의 music_gain_db/sfx_gain_db(각 -40–18)와 duck_sfx를 사용한다. sidechain은 SFX가 들어올 때 음악 버스를 낮춘다. 기본 master_gain과 편집 버스 gain을 혼동하지 않는다. 음악·SFX 각각의 구간 RMS, 최종 LUFS/true peak를 측정하고 실제 소리도 별도로 듣는다. 신호가 존재한다는 검사는 좋은 소리·모바일 가청성을 입증하지 않는다.

## 필수 검수

휠 수/접지/축 흔들림/펜더·캐빈 관통, 루프와 유리 교차, 앞뒤 외관 일치, 전체 회전 중 프레임 이탈, 액션과 소리의 시작·끝, 엔진과 음악의 마스킹, 의도한 실내 음량 대비를 확인한다. 정지 프레임과 전체 재생은 별도다. 시점 순서 변경 시 동일한 프레임·연기 상태가 재현되어야 한다. 사용자 제작 지시는 미감 승인과 구별한다.
