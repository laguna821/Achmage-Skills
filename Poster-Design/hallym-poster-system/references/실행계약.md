# 실행 계약

요청:
```json
{"mode":"poster-create","poster":{"kind":"event","size":"A2","title":"제목","facts":[{"label":"일시","value":"확인된 일정"}],"message":"핵심 메시지","sections":[{"title":"내용","body":"본문","span":6}],"footer":"문의/출처"},"outputDir":"새 결과 폴더","dpi":150}
```
kind event/recruitment/research. 제목 필수. 단순 학술 모드는 sections 필수. 계층형 학술은 groups에 방법·근거·한계를 보존한다. 선택 eyebrow, subtitle(학술 authors), messageLabel, cta, image, figureCaption, chart(title/labels/values/caption), shareTitle/shareDescription, publishUrl.
모든 내용은 일반 텍스트이며 HTML로 실행하지 않는다. image는 단일 로컬 이미지; URL 다운로드는 에이전트가 별도 허가 범위에서 수행한다.
제목 배치: `titleLayout` 기본값 `auto`는 제목 안의 개행을 공백으로 연결하고, 종이에서52단위 이상으로 한 줄이 가능하면 폭에 맞춰 제목만 조정한다. 한 줄이 불가능하면 기존 제목 크기로 자연 줄바꿈한다. 화면 재조판에서는 글자 크기를 줄여 한 줄을 강제하지 않고 폭에 맞게 줄바꿈한다. `preserve`는 사용자가 명시한 개행과 기존 프로필 크기를 보존한다. PDF·HTML·접근성 본문의 글자 내용은 동일하게 유지한다.
기본 본문 묶음1~16, chart 비음수 수치1~6. 기존 outputDir 덮어쓰기 거부.
dpi72~300,100M 픽셀 한도. 사용자가 요청한 규격은 몰래 바꾸지 않는다.

결과 poster.html / poster.pdf / poster.png / og-해시.png / poster-spec.json / layout.json / design-advice.json / share-manifest.json / result.json.
generated-awaiting-visual-review는 생성 성공일 뿐 실제 시각 검수 완료가 아니다.
needs-content-or-layout-adjustment/2는 내용·배치 수정 필요. error/1은 실행 실패. 둘 다 원본은 보존하고 새 작업으로 수정 근거를 기록한다.
EJ 공식 실행은 자료를 작업 폴더에 복사·해시 고정 후 계획과 영수증을 자동 작성한다. 사용자가 계획 파일을 수작업으로 만들지 않게 한다.

## 게시 준비
scripts/prepare_pages.py 요청 JSON → 새 staging/<sourcePath>/slug/에 index.html, og-해시.png, poster.pdf를 준비한다. sourcePath는 확인된 루트(빈 문자열) 또는 docs이며 기존 설정을 따른다. 기본값은 docs지만 이 프로젝트의 등록값은 루트다. .nojekyll은 newRepository:true인 새 저장소에만 추가한다. 기존 저장소의 README 기반 홈페이지/Jekyll을 비활성화하지 않는다. 공개 전 검토할 목록/해시/목표 URL을 남기며 이 명령은 네트워크 업로드를 하지 않는다.
publishUrl은 실제 게시 URL일 때만 명세에 넣는다. 로컬 시연은 생략하며 share-manifest에 needs-publish-url 표시.
배포 후 정확한 페이지/이미지가 인증 없이 접근되는지 확인하고 카카오 URL 메타정보 도구/실제 공유 카드로 검수한다. 캐시 문제면 해시 이미지 파일명과 공식 캐시 초기화 절차 사용.

## 복합 위계 입력 (고밀도 기본)
poster.groups: 2~14개의 의미 묶음. 각 묶음은 title(필수), kicker, lead, body, items, note, priority(1~4), span(auto/2/3/4/6), tone(auto/navy/blue/teal/pale/plain).
items는 최대12개이며 label/text/note로 구성한다. 짧은 label은 굵게 본문 앞에 놓고 긴 label은 별도 줄로 측정한다.
전체 제목 level1, 영역 제목2, 핵심 문구3, 세부 항목4, 조건·주석5. 글자 색만으로 분류하지 않으며 면적·굵기·배치도 함께 쓴다.
groups 모드에서 facts/sections/message/chart/image/figureCaption을 혼합하면 오류로 멈춘다. 내용이 조용히 빠지지 않도록 한 방식으로 명세를 작성한다. 사진·수치 차트가 주된 포스터는 단순 모드의 검증된 도형/이미지 배치를 사용한다.
복잡한 요구는 examples/hierarchy-dense.json부터 시작한다. JSON에는 사용자 실제 원고만 넣고 예제 문장을 사실처럼 남기지 않는다.

계층형 HTML은 responsive-layouts.json에 화면 후보와 필드 보존을 기록한다. PDF·PNG는 원본 종이 규격이며 모바일 HTML의 현재 비율로 바뀌지 않는다. [모바일 화면 계약](모바일-화면계약.md) 참조.


프로젝트 게시 설정이 활성화되면 공식 poster 실행기는 생성 성공 후 게시준비와 publish-plan.json을 자동 작성한다. 요청 `publish:false`는 비공개/로컬 전용, `publish:{"slug":"영문-고유경로"}`는 작품 경로 지정이다. 이 로컬 단계는 업로드가 아니다. 에이전트가 시각 검수 후 연결된 GitHub 도구로 계획의 files만 게시하고 실제 URL·OG를 검사한다. 실패하면 로컬 결과를 보존한다.


## PDF 저장 호환성
게시용 PDF 버튼은 같은 출처의 실제 HTTPS PDF 파일을 직접 연결한다. data: PDF 다운로드만으로 iPhone Safari 호환을 보장하지 않는다. 다운로드 속성을 지원하면 저장을 시작하고, 미리보기로 열리는 브라우저를 위해 도움말에 ‘PDF 새 탭에서 열기’와 iPhone ‘공유 → 파일에 저장’, Android Chrome ‘더보기 → 다운로드’를 제공한다. 별도 클릭을 지연시키는 fetch/비동기 팝업은 사용하지 않는다. 오프라인 HTML은 내장 PDF를 동기적으로 Blob URL로 변환한다. PC Chromium 검수만으로 iOS/Android 실기기 성공을 선언하지 않는다.
게시 준비에서 PDF 해시를 URL 쿼리에 붙여 교체 후 캐시를 구분한다. 실제 application/pdf 응답, 다운로드 바이트 일치, 공개 링크의 JavaScript 비활성 상태, 별도 열기 링크를 검사한다.
