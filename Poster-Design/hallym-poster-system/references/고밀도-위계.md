# 고밀도 위계 설계

## 원고를 먼저 구조화한다
자료에서 주장/안내, 판단에 필요한 근거, 하위 항목, 적용 조건과 출처를 추출한다. 원고의 각 문장·숫자가 어느 묶음에 들어갔는지 대조한다. 작성자가 준 관계를 보존하고 새로운 장학 조건·기한·연구 결론을 만들지 않는다.

에이전트가 의미 분류와 우선순위를 정하고, 측정 엔진이 들어가는 배치를 계산한다. 엔진이 자연어의 사실이나 중요도를 저절로 이해한다고 주장하지 않는다. 사용자는 원고와 원하는 결과만 말하면 된다.

1. 전체 제목: 한눈에 주제, 최상위 큰 글자.
2. 영역 제목: 모집 분야/일정/연구 방법처럼 서로 다른 정보 덩어리를 색 헤더·괘선으로 구별.
3. 핵심 문구: 마감일/주요 혜택/핵심 결과를 더 굵고 크게.
4. 세부 항목: 굵은 짧은 항목명과 이어지는 설명. 같은 의미끼리 가까이 둔다.
5. 조건·주석: 적용 조건/예외/출처를 작은 글자로 보존. 중요한 제한을 배경과 섞어 숨기지 않는다.

## 면적과 색을 의미에 연결한다
priority1 핵심/마감/결과는 넓은4~6열 및 강한 면, priority2 비교 대상은 서로 대응하는 카드, priority3 절차/근거, priority4 보조 안내·출처. 기본 tone은1 navy,2 blue,3 pale,4 plain이며 같은 수준의 대조에는 blue/teal을 함께 쓴다. 한 장에 모든 카드를 강한 색으로 칠하지 않는다. 색과 크기 두 신호가 충돌하면 원고의 중요도를 다시 확인한다.

6열에서 전체띠, 대등한3+3, 주·보조4+2 또는2+4, 짧은3항목2+2+2를 비교한다. 고정 순서를 보존하므로 먼저 에이전트가 읽기 순서를 설계한다. 긴 내용을 작은2열에 몰아넣지 않는다. 출력 후 아래쪽에 더 중요한 정보가 묻히지 않았는지 본다.

## 밀도 조정 순서
실측 줄바꿈 → 의미 묶음/읽기 순서 정돈 → 폭 배분 → 짧은 항목명의 행내 배치 → 정해진 여백/행간/타입 프로필 순으로 조정한다. 긴 소제목을 억지로 줄이지 않는다. 필수 수치·조건·출처 삭제 금지. 본문20단위 아래로 축소 금지. 실패 시 필수 정보를 유지한 구체적 배치/중복 문구 정리안을 제안한다. 사용자 지정 규격이나 분량을 몰래 바꾸지 않는다.

## 검수와 한계
hierarchy-dense.json은 모집 안내처럼 항목과 조건이 중첩된 가상 원고다. 55개 텍스트 필드, 1,259자(공백 제외), 참고 이미지 수기 전사624자의2.02배다. 숫자는 정보량의 근사치이며 모든 내용이 같은 난이도라는 뜻이 아니다.

자동: 한 장·mm·필드 보존·글꼴·범위/겹침·양 테마 대비. 시각: 390×844/320×568/1440×900에서 제목, 주요색면, 비교카드, 항목명, 주석 차이. 동일 카드 반복이나 단순 용량 시험만으로 디자인 통과를 선언하지 않는다.

한 장 전체 보기는 비율을 유지해 모든 글자·도형이 함께 작아진다. 390px에서 본문20단위는 약7.5px이며, 작은 본문의 정독에는 확대가 필요하다. 확대는 전체 보기의 위계 실패를 덮는 수단이 아니다. 인쇄/PDF의 실제 물리 글자 크기와 휴대폰 전체 보기 글자 크기는 별도 기록한다.
