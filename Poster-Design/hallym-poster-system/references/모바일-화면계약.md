# 모바일 화면 계약

인치·모델명·OS 이름으로 크기를 추측하지 않는다. 실제 가시 영역의 CSS 폭/높이와 안전 여백을 사용한다. 기본 PDF는 종이 규격 그대로이며 화면 재배치가 PDF·인쇄에 섞이지 않는다.

## 화면 맞춤
계층형 groups 입력은 세로로 긴 폰, 짧은 폰, 펼친 정사각형에 가까운 화면에 대한 실측 배치 후보를 생성한다. 작은 화면의 물리 인치는 검출하지 않는다. 240~1024 CSS px 폭, 사용 가능 높이/폭0.7~2.9 범위에서 맞는 후보를 고르고 행 높이의 남는 공간만 분배한다. 범위 밖이나 후보가 없는 경우 종이 한 장 contain을 유지하며 내용 누락으로 채우지 않는다.

본문30→28→26→24→22→20 논리 단위를 검토해 들어가는 가장 큰 글자를 고른다. 인쇄용 density 고정과 별개인 화면 전용 후보다. 제목·색·정보 순서와 모든 문자열을 보존한다. 바깥 SVG는 균일 비율 확대/축소만 한다. 추가 공간은 카드 배경 높이와 행/하단 위치에 분배하며 글자와 이미지의 종횡비를 늘리지 않는다.

기본은 화면 배치, V/종이 버튼으로 원래 인쇄 구성을 볼 수 있다. PC 폭이1024를 넘으면 종이 배치를 기본으로 쓴다. Z 확대는 현재 배치를 유지한 채 이동해서 읽는다. 확대 중 자동 재조판을 하지 않는다. 작은 폰에서2배 원고 전체를 큰 본문으로 읽게 한다는 보장은 하지 않는다.

## 주소창·안전 영역
CSS100svh/100dvh fallback과 VisualViewport 폭·높이·offset을 연결한다. 주소창 표시/숨김, 회전, 창 크기 변경 시 재계산한다. VisualViewport.scale이1을 벗어나는 네이티브 핀치 중에는 배치를 고정한다. safe-area-inset 네 방향과 최소8px 여백으로 노치/홈바를 피한다. 포스터 도구는 작은 ⋯ 하나로 표시하고 터치 영역은44×44px를 유지한다. 상단 전체 도구 행을 예약하지 않는다. 화면 후보에는 제목 오른쪽 작은 영역만 확보하며 실제 글자·이미지와 겹치지 않는 모서리를 선택한다. 패널 안에 테마·PDF·확대·종이 보기·인쇄·도움말을 제공한다. 바깥 클릭·Esc·초점 이동으로 닫고 사용 중 타이머로 숨기지 않는다. 열기/닫기로 본문을 재조판하지 않는다. 모든 크기에서 toolsClear=true와 실제 화면을 검수한다.

브라우저가 viewport segments를 노출하는 이중 화면은 왼쪽/위쪽 한 개 연속 영역에 배치해 힌지 위에 글자를 걸치지 않는다. 해당 API가 없는 기기나 웹뷰의 물리 힌지는 자동 검출을 보장하지 않는다. 사용 가능한 뷰포트가 달라지면 그 영역에는 다시 맞춘다.

## 검증 범위
320×480,320×568,390×680→844,640×720,720×640,1440×900 크기와 변경 상태를 확인한다. 가시 텍스트·제목·하단이 현재영역 안에 있고 PDF 필드 집합과 같은지 확인한다. 실제 iPhone Safari/Android Chrome의 주소창·노치·핀치·힌지 검증과 데스크톱 뷰포트 검증을 구별한다. 이미지 뷰어/카카오 앱의 외부 검은 배경은 HTML이 제어할 수 없다.

## PDF 저장 호환성
게시용 PDF 버튼은 같은 출처의 실제 HTTPS PDF 파일을 직접 연결한다. data: PDF 다운로드만으로 iPhone Safari 호환을 보장하지 않는다. 다운로드 속성을 지원하면 저장을 시작하고, 미리보기로 열리는 브라우저를 위해 도움말에 ‘PDF 새 탭에서 열기’와 iPhone ‘공유 → 파일에 저장’, Android Chrome ‘더보기 → 다운로드’를 제공한다. 별도 클릭을 지연시키는 fetch/비동기 팝업은 사용하지 않는다. 오프라인 HTML은 내장 PDF를 동기적으로 Blob URL로 변환한다. PC Chromium 검수만으로 iOS/Android 실기기 성공을 선언하지 않는다.
게시 준비에서 PDF 해시를 URL 쿼리에 붙여 교체 후 캐시를 구분한다. 실제 application/pdf 응답, 다운로드 바이트 일치, 공개 링크의 JavaScript 비활성 상태, 별도 열기 링크를 검사한다.
