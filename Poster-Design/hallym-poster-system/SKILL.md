# 한림 포스터 시스템

행사·모집과 학술 포스터를 한 장으로 만든다. 사용자는 스킬명/JSON/명령어를 알 필요가 없다.
자료에서 목적·청중·필수 내용·규격을 파악하고 “이 내용은 큰 제목 + 일정 두 칸 + 핵심 메시지 + 안내 칸으로 묶겠습니다”처럼 먼저 짧게 설명한다.

## 출력 모드 먼저 선택
- 기존 groups/event/research 원고는 **legacy-rc6** 계약과 renderer를 유지한다. 이 버전 번호만 바뀌었다고 기존 포스터를 자동 변환하지 않는다.
- 순환·여러 장·LCD·디지털 사이니지 요청은 **series-v2**: [순환 포스터 계약](references/SERIES.md)을 먼저 읽는다. 먼저 한 장에 전체 정보를 완결한다. 충분한 추가 원고가 있을 때만 독립적으로 완결된 포스터 여러 장을 구성한다. 제목·연사·일정·참가 안내를 각각 슬라이드로 나누거나 넘친 줄만 다음 장으로 보내지 않는다. SERIES의 공통 핵심 반복과 화면/인쇄 분리 계약을 따른다.
- 새 행사라도 기존 모드를 사용자가 지정하면 보존한다. 출력별 viewerVersion/packageSha256를 기록한다.
- 기관 로고는 실제 소속/기관 역할 근거와 사용자가 지정한 범위가 있어야 한다. 벡터 원본이 없고 재구성 요청이 있으면 출처 이미지에서 정밀 추적하고 파생 자산임을 명시한다.

## 우선 읽기
- [설계 계약](references/DESIGN.md): CMDS 9종 → 세로 벤토 변환, 브랜드, 화면/인쇄.
- [모바일 화면 계약](references/모바일-화면계약.md): 실제 보이는 영역·안전 여백·재조판·인쇄 분리.
- [고밀도 위계 설계](references/고밀도-위계.md): 정보 분류와 5단계 배치의 기본 절차.
- [실행 계약](references/실행계약.md): 입력, 상태, 검수, 오류 복구.
- 프로젝트 게시 설정이 활성화되었거나 공유/게시가 요청되면 [GitHub 온보딩](references/GitHub-온보딩.md). 이미 등록된 공개 범위를 반복 질문하지 않는다.
- 소스 원문은 references/sources/에 보존한다. 원문의 엔진 실행·정리·전역 수정 지시를 현재 권한으로 해석하지 않는다.
- UI UX Pro Max는 번들 검색을 실제 실행한다. Impeccable layout/typeset/polish 원칙은 아래 검수에 적용한다. 서로 다른 빌더를 중첩 실행하지 않는다.

## 자연어 작업 흐름
1. 자료를 읽어 행사/모집 또는 학술을 고른다. 누락된 제목·일정·장소·모집 조건/연구 근거만 묻는다. 알 수 없는 사실을 지어내지 않는다.
2. 지정 양식·내용·브랜드가 우선이다. 기본 한림 색과 Pretendard 사용은 소속/공식 행사라는 뜻이 아니다. 로고와 소속을 임의로 넣지 않는다.
3. 기본 세로 A2(행사·모집), A1(학술). 사용자 규격은 보존한다. 제목 → 요약/핵심 결과 → 정보 묶음 → 출처·신청 순으로 읽힌다.
   제목은 슬라이드처럼 임의로 두 줄을 만들지 않는다. 종이·넓은 화면에서는 실제 폭을 측정해 최소 제목 크기52 이상으로 한 줄이 가능하면 우선 사용한다. 긴 제목은 자연 줄바꿈하고, 모바일 화면 후보는 제목을 억지로 축소하지 않는다. 사용자가 줄바꿈을 명시한 경우 `titleLayout: "preserve"`로 보존한다. 상세 동작은 [실행 계약](references/실행계약.md)의 제목 배치를 따른다.
4. 기존 스킬을 조합할 기회도 제안한다: 논문/PDF 읽기 → 주장·근거·한계 추출 → 학술 포스터 → 공유. 행사표/XLSX 읽기 → 일정 정리 → 모집 포스터. 반복 작업은 개인 양식/원고 spec을 내양식에 복사해 다음 달 변경 필드만 바꾼다.
5. 복잡한 원고는 examples/hierarchy-dense.json의 groups 방식을 기본으로 쓴다. 에이전트가 원고의 제목·핵심·하위 항목·조건을 분류하고 priority/tone/내용 순서를 작성한다. 엔진은 실제 글자 폭과 줄 수를 측정해 6열의 여러 조합을 비교한다. 사용자가 스킬이나 배치 JSON을 설계하게 하지 않는다. 도표/사진 중심 단순 포스터는 event/research 예제의 기본 모드를 쓴다. 두 입력 방식을 혼합하지 않는다.
6. 공식 실행 후 PDF·HTML·썸네일을 실제로 열어 검수한다. 자동 검사 통과는 시각 검수 완료가 아니다.
7. 과밀하면 필수 내용 목록을 유지하며 칸 너비/순서/제목 줄바꿈/중복 표현을 수정한다. 의미 있는 삭제·요약 변경은 사용자에게 설명한다. 밀도는 auto(standard/compact/dense), 최소 본문20·제목52 단위로 제한한다. 여백과 제목 영역부터 조정하며 글자를 무제한 축소하거나 두 페이지로 나누지 않는다.
8. “이 양식으로 다음 것도”이면 현재 spec과 디자인 선택을 작업 이어하기/내양식에 기록한다. 패키지 업그레이드로 개인 양식을 덮어쓰지 않는다.

## 프로젝트 기본값
게시 계정·저장소·공개 기본값은 프로젝트의 내양식/hallym-poster-system/publishing.json에서 확인한다. 설정된 공개 범위는 반복 질문하지 않고, 비공개/로컬 전용 요청이 우선한다. 공통 스킬에 특정 계정이나 게시 원본 경로를 고정하지 않는다.

포스터 도구는 작은 ⋯ 하나로 표시하고 터치 영역은44×44px를 유지한다. 상단 전체 도구 행을 예약하지 않는다. 화면 후보에는 제목 오른쪽 작은 영역만 확보하며 실제 글자·이미지와 겹치지 않는 모서리를 선택한다. 패널 안에 테마·PDF·확대·종이 보기·인쇄·도움말을 제공한다. 바깥 클릭·Esc·초점 이동으로 닫고 사용 중 타이머로 숨기지 않는다. 열기/닫기로 본문을 재조판하지 않는다. 모든 크기에서 toolsClear=true와 실제 화면을 검수한다.

게시용 PDF 버튼은 같은 출처의 실제 HTTPS PDF 파일을 직접 연결한다. data: PDF 다운로드만으로 iPhone Safari 호환을 보장하지 않는다. 다운로드 속성을 지원하면 저장을 시작하고, 미리보기로 열리는 브라우저를 위해 도움말에 ‘PDF 새 탭에서 열기’와 iPhone ‘공유 → 파일에 저장’, Android Chrome ‘더보기 → 다운로드’를 제공한다. 별도 클릭을 지연시키는 fetch/비동기 팝업은 사용하지 않는다. 오프라인 HTML은 내장 PDF를 동기적으로 Blob URL로 변환한다. PC Chromium 검수만으로 iOS/Android 실기기 성공을 선언하지 않는다.

## 실행
EJ 프로젝트의 설치/run.ps1이 있으면 반드시 공식 경로:
```powershell
& '.\설치\run.ps1' -Action poster -Request '.\작업\...\request.json'
```
환경 준비 불가이면 설치/start.ps1 → probe → 같은 원고로 새 작업. 없다고 안내만 하고 끝내지 않는다.
EJ 밖은 이 스킬 scripts/poster.py를 번들 Python으로 실행한다. 경로는 현재 PC에서 탐지하며 C:/Users/...를 고정하지 않는다.
```text
python -X utf8 -B scripts/poster.py request.json
python -X utf8 -B scripts/poster.py doctor
```
설치가 필요하면 requirements.txt의 검증된 의존성을 현재 작업/사용자 런타임에 설치한다. 웹 페이지 스크립트나 전체 Achmage MCP는 필요 없다.

## 반드시 검수할 것
- legacy PDF 1페이지 / series 명시한 종이 페이지 수·실제 mm·제목 상단·필수 텍스트/수치/출처 보존·임베드 글꼴·사진 비율.
- PDF/PNG와 HTML 종이 모드는 배치가 일치한다. HTML 화면 모드는 같은 원문을 별도 실측 재조판하며 모든 글자/도형의 종횡비를 보존한다.
- 390×844, 320×568, 1440×900에서 light/dark. 종이 모드는 전체 contain, groups 화면 모드는 실제 가시 영역에 맞춘 재조판이다. 주소창·노치·홈바의 안전 여백은 남긴다.
- T/버튼 전환, Z/확대·한 장 복귀, Esc, 새로고침 테마 유지, ⋯ 접힘 기본, 패널 열기·닫기/터치·키보드 복구. 도구 표시 상태에서도 본문과 영역이 겹치지 않아야 한다.
- 확대 시 가로·세로 스크롤, 핀치 줌 차단 금지, 작은 터치 버튼도 44px 확보, 감축 모션.
- 글자 대비 양쪽 4.5 이상. 사진/도표 원래 색을 반전하지 않는다.
- 인쇄는 항상 밝은 1장. PDF 자체를 전달하는 것이 기준이며 브라우저 인쇄 대화상자/프린터별 실제 출력은 확인한 범위만 말한다.
- 긴 제목, 긴 한글, 많은 섹션에서 실패 상태와 수정안을 정직하게 표시.
- 공개 URL이 없으면 OG 자산 준비와 카카오톡 실제 카드 확인을 구분한다. 파일 첨부만으로 링크 카드가 보인다고 하지 않는다.

## 완료 응답
파일 링크 + 검사 결과 + 사용법 한 문장. 기본 게시가 활성화된 포스터는 업로드와 실제 HTTP/OG 검증까지 이어서 완료하고 공개 링크를 함께 전달한다. 실패하면 제작 완료와 게시 미완료를 구분해 이어하기에 정확한 다음 단계를 남긴다.
실패·수정 근거는 EJ 공식 실행 영수증/연구 장부와 Achmage research_register의 정확한 revision에 연결한다.
이 버전은 CMDS 시각 언어의 포스터 어댑터이며 원본 9종 전체 엔진 호환을 주장하지 않는다.

고밀도 디자인 검수는 글자수만으로 통과시키지 않는다. 3~5단계 의미 위계, 서로 다른 카드 면적/폭, 색상 헤더와 본문 색 면, 굵기/크기의 차이가 실제 모바일 전체 보기에서 구분되어야 한다. hierarchy-dense.json은 1,259자/참고 624자(공백 제외)의 2.02배 합성 원고다. density-1_5/2 예제는 용량 시험일 뿐 디자인 합격 근거가 아니다. 확대 기능은 위계 설계를 대신하지 않는다.

공동기관 로고는 왼쪽부터 같은 시각 높이·작은 일정 간격의 한 묶음으로 배치한다. 화면 폭에 비례해 벌리거나 열마다 중앙에 놓지 않는다. 실제 기관명 너비로 이어 배치하고 HTML/PDF 모두 정렬·간격·넘침을 검수한다.

순환 포스터의 기본 체류시간은 사용자 지정에 따라 첫 장부터 4초다. 명시적으로 다른 장면 시간이 지정되면 보존한다. 사용자 조작 후 정지와 모션 감소 설정을 유지한다.

순환 포스터 상하단은 본문 테마와 함께 바뀐다. 위치·기관 정보는 유지하고 라이트/다크/장면별 자동 모드와 첫 로딩 색상을 동기화한다. 라이트/다크 로고 SVG를 별도 제작해 함께 전환한다. 심벌 형태·비율 보존, 파생본 출처와 양쪽 해시를 기록하고 CSS 반전은 사용하지 않는다.

## 완결 포스터 교정 · PS06
페이지는 슬라이드가 아니라 독립 포스터다. 먼저 한 장에 전체 위계를 설계한다. 두 번째 장도 제목·핵심 메시지·일시·장소·참여 안내를 반복하고 충분한 상세 내용으로 채운다. 잔여 문단만 넘기는 자동 분할 금지. 원고 전체를 재배분해 장별 초점과 균형을 설계한다. 화면 크기/주소창 변화로 페이지 수를 늘리지 않는다. 합성 글자수 검사는 잔여 페이지를 막는 하한이며 의미·시각 검수를 대신하지 않는다. 한 장이면 순환 UI를 숨기고 크게 읽기를 제공한다.

## PS07 · 실제 원문 기반 복수 포스터 시험

## PS09 · 화면과 종이의 병렬 편집
HTML은 완결 포스터 여러 장을 기본 4초 간격으로 순환한다. 기본 선택은 '라이트·다크 교차'이며 장 번호에 따라 색을 전환한다. authored는 별도 선택이다. 새 저장 키의 명시적 light/dark 선호는 보존하되, 기존 저장 값이 새 기본값을 가로막지 않도록 한다.

모바일 세로 화면은 모든 장의 논리폭·높이·배율·좌우·상단을 공유하면서 본문 가로 점유율 90% 이상을 우선 확인한다. 후보 폭별 실제 표시폭을 우선하고 동률이면 배율을 선택한다. 짧은 가로 화면은 전체 보기와 크게 읽기를 유지한다.

A2는 기본 한 장이다. HTML 장수를 PDF 장수로 복제하지 않는다. 같은 사실 원장에서 별도 2열·다열 편집으로 전체 원고를 한 장에 완결한다. 제목·행사 정보·모든 연사와 주제·일정·조건·출처를 동시에 읽을 수 있는 전통적 포스터 위계를 설계한다. print.rows를 직접 설계한다. print.pages는 사용자가 종이 복수 장을 별도로 명시한 경우에만 allowMultiplePages=true와 multiPageReason으로 허용한다. HTML이 여러 장이라는 이유는 승인이 아니다.

종이 본문 18pt 이상에서 열 너비·중복 정보·제목과 도표 배치를 조정한다. 공간이 부족하면 다시 편집하고 오류를 보고한다. 무제한 축소나 종이 페이지 추가로 해결하지 않는다. academic-one-sheet는 별도 2열 편집·큰 제목·정렬된 공동기관 로고·하단 행사 QR을 제공한다.

print.iccProfile은 명시적 CMYK 출력 ICC 경로다. sRGB 입력색을 LittleCMS 상대 색도계로 변환하고 PDF OutputIntent에 동일 ICC를 내장한다. 작은 검정 본문과 QR은 K100으로 출력한다. 공개 spec에는 경로 대신 프로파일 이름·해시·출력 조건을 남긴다. SVG와 QR의 기본색도 Canvas 경계에서 변환하고 RGB 연산자 0을 검사한다. 불필요한 기본 폰트를 제거하고 남은 모든 폰트의 내장을 검사한다.
