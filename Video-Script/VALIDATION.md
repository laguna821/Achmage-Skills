# 1.2.0 검증 범위

검증일: 2026-11-11 ~ 2026-11-12. Windows, Python 3.13, Node.js 26, Chromium 계열 브라우저에서 만들고 시험했습니다.

## 확인한 내용

- **블라인드 작성 시험 (한국어, 두 차례):** 스킬 폴더만 읽은 작성자 셋이 갈래가 다른 대본 셋을 썼습니다(카페 소음 5분 A1, 멜리타 벤츠 2분 30초 C, 노먼 도어 90초 D2). 첫 차례에서 막힌 곳을 스킬에 반영하고 둘째 차례를 다시 썼습니다. 둘째 차례 대본은 모두 자동 검수 실패 0입니다.
- **영어 대본 시험:** 스킬 폴더만 읽은 작성자 셋이 영어 대본을 썼습니다(Espresso 150초 C, Desire Paths 90초 D1, Cheonggyecheon 86.5초 B, 손본 뒤 89초). 셋이 서로 모르는 채 같은 곳(영어 카드의 마침표, 코드에만 있던 영어 기준값, 한국어 전용 검수, 찾아 쓰는 실사의 유형)에서 막혔고, 그 결과로 영어 규칙과 검수를 고쳤습니다. 손본 대본 셋 모두 실패 0입니다.
- **실제 제작 두 편:** 노먼 도어(90초, 한국어, 그린 그림)와 Espresso(150초, 영어, 실사와 도면과 도해)를 Motion Art Director 4.1.0으로 끝까지 렌더했습니다. 대본과 다르게 만들어야 했던 곳을 기록했고, 그것을 스킬의 제작 인계 칸과 검수로 되돌렸습니다. 기록: `examples/*/production-notes.md`.
- **단독 실행:** 스킬 폴더만 빈 곳에 복사해 `build_sheet.py`로 대본 둘의 검수(`--lint-only`), 카드 읽기(`--print-cards`), 가편집 시트 만들기를 실행했습니다. 모두 정상 종료했고 스킬 밖의 파일을 읽지 않습니다. Python 표준 라이브러리만 씁니다. 시트 HTML은 외부 자원을 불러오지 않습니다.
- **예제 대본 다섯 편의 검수 (1.1.0 기준, 1.0.0과 같음):** 노먼 도어 제작본 실패 0 / 주의 7, 노먼 도어 고친 판 실패 0 / 주의 2, Espresso 실패 0 / 주의 2, Desire Paths 실패 0 / 주의 3, Cheonggyecheon 실패 0 / 주의 3. 남은 주의와 그 까닭은 대본마다 `meta.review_notes`에 있습니다.
- **사례집의 인용 한도 (1.1.0):** 사례집을 만든 스크립트가 영상 159편 가운데 CC BY 4.0으로 공개된 14편(ESO, ESA/Hubble)을 뺀 145편을 검사했습니다. 사례집 전체에 그대로 실린 화면 문장과 말소리가 영상마다 15% 이내(짧은 영상은 한국어 80자, 영어 160자 이내)입니다. 한도를 넘는 영상은 0편이고, 전체로는 원문의 11.2%입니다. 줄이기 전의 분석 원본은 94편이 한도를 넘었고 9편은 절반 넘게 실려 있었습니다. 영상별 뼈대 표에는 원문이 없습니다.
- **A3 갈래 블라인드 시험, 사례집 포함 (1.1.0):** 스킬 폴더만 읽은 작성자가 쿼티 자판 5분 대본(A3, 한국어)을 썼습니다. 자동 검수 실패 0 / 주의 0, 길이 321초입니다. 사례집에서 읽은 것은 안내문, 역사채널e 채널 분석, 영상별 구조 한 편입니다. 작성자의 기록으로는 사례집이 바꾼 결정이 둘입니다: 요즘의 속설을 실제로 적은 문헌의 문장으로 통념을 세운 것, 끝에 이견을 밝히는 카드를 따로 세운 것. 나머지 결정은 규칙 문서만으로 정해졌다고 적었습니다. 작성자가 막힌 열 군데 가운데 문서끼리 어긋난 곳(비트 시각의 겹침, 둘째 꺾임의 자리, 이름 카드, 출처 상태 값, 출처 표기의 길이, 해석이 어긋날 때의 제목, 강조의 수, 인용이 많을 때의 길이)을 고쳤습니다.
- **조사 원자료 (1.2.0):** `corpus/`에 298개 파일(화면 문장 원문 로그 159, 자막 전사 103, 채널 분석 원본 30, 보고서, 색인, 목록, 안내문)을 넣었습니다. 로컬 경로가 남아 있지 않은지, 사례집의 영상별 구조 159편이 가리키는 원문 로그가 모두 있는지 확인했습니다. 화면 캡처 묶음은 넣지 않았습니다. 사례집의 인용 한도(영상마다 15%)는 사례집 안에만 적용되며, `corpus/`는 원문 기록 그대로입니다.
- **패키지:** `tools/verify_package.py`가 스킬 폴더, `PACKAGE-MANIFEST.json`, 설치 ZIP의 파일과 SHA-256이 서로 같은지 확인합니다.

## 확인하지 않은 내용

- 갈래 A2, L과 영어 A 갈래로는 대본을 써 보지 않았습니다. A3, B, D1은 대본까지만 썼고 영상으로 만들지 않았습니다.
- 사례집을 읽고 쓴 대본과 읽지 않고 쓴 대본을 견주는 시험은 하지 않았습니다. A3 시험 한 번의 작성자 기록이 전부입니다.
- 사례집의 인용 한도는 스스로 정한 기준입니다. `corpus/`에 방송 원문 기록을 실은 것은 저장소 소유자의 결정이며, 법률 검토를 받은 것이 아닙니다.
- 자동 검수는 문장의 맛을 보지 못합니다. 영어에서는 평가 표현(여덟 낱말)과 당부 표현(여섯 구절)만 잡습니다. 수동 검수(`references/05` 2절)가 필요합니다.
- 다른 PC에서 Claude Code 플러그인 설치와 자동 선택, Codex의 자동 선택은 확인하지 않았습니다.
- 예제 영상의 화면은 정지 프레임으로 검토했습니다. 소리와 미감은 제작한 쪽에서 판정하지 않았습니다(노먼 도어의 음악은 사람이 세 판을 들어 보고 골랐습니다).
- 가편집 시트는 Chromium 계열에서만 열어 보았습니다.

이번 공개는 검증한 파일의 배포입니다. 새 주제로 쓴 대본의 품질을 보증하지 않습니다. 대본마다 스킬의 검수와 수동 검수를 다시 하세요.
