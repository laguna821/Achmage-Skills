# 영상 대본 작법 (화면 문장 대본)

내레이터 없이 **화면 문장과 장면만으로** 한 편을 완결하는 영상의 대본을 쓴다. 이 스킬의 산출물은 대본이다. 장면은 대본에 맞춰 제안만 하고, 실제 제작은 `motion-art-director` 같은 제작 스킬에 넘긴다.

근거는 27개 채널 159편의 화면 문장 분석이다(지식채널e, 역사채널e, 뉴스타파 5 Minutes, AJ+, NowThis, Brut, ESOcast Light 등). 규칙마다 어디서 나왔는지는 `references/`에 적혀 있다.

## 이 스킬이 푸는 문제

영상에 넣은 문장이 약한 까닭은 대개 넷 중 하나다.

1. 첫 카드가 주제를 소개한다.
2. 카드마다 문장이 끝나 있어 다음 카드를 기다릴 이유가 없다.
3. 장면에 보이는 것을 문장이 다시 말한다.
4. 마지막 카드가 요약이나 당부다.

내레이션 원고를 잘라 화면에 올리면 넷이 한꺼번에 일어난다. 화면 문장 대본은 내레이션 원고와 다른 글이고, 밀도는 그 절반에서 3분의 1이다.

## 작업 순서

아래 8단계를 차례로 한다. 단계를 건너뛰지 않는다. 특히 3단계(설계 결정)를 적지 않은 채 카드를 쓰기 시작하지 않는다.

### 1. 브리프 확인

다섯 가지를 확인한다. 사용자가 주지 않은 것은 스스로 정하고, 정한 내용을 산출물에 적는다. 이것 때문에 되묻지 않는다.

| 항목 | 정할 것 |
|---|---|
| 길이 | 90초 / 2~3분 / 5분 / 7분 이상 |
| 무엇을 하는 영상인가 | 뜻을 묻는다 / 일을 전한다 / 사람이나 사물의 이야기를 한다 / 발견이나 개념을 설명한다 |
| 통념 | 시청자가 이미 믿고 있는 것. 없으면 "없음" |
| 화면 재료 | 실사, 기록 영상, 일러스트, 도해, 스톡, 생성 이미지 가운데 쓸 수 있는 것 |
| 빌려 쓸 말 | 인용, 사료, 인터뷰, 통계 가운데 확보된 것 |

### 2. 자료 묶음 확보

대본에 들어갈 **수치, 날짜, 인용, 고유명사**는 출처가 있는 것만 쓴다.

- 사용자가 자료를 주었으면 그 안에서 쓴다. 모자라면 직접 조사해 출처를 붙인다.
- 확인하지 못한 것은 쓰지 않는다. 꼭 필요하면 카드의 `note`에 "미확인"이라고 적고 검수에서 드러나게 둔다.
- 인용문을 지어내지 않는다. 가상 화자의 말(시청자의 속마음, 통념)은 지어내도 되지만 `kind`를 `편집`으로 두고 실존 인물의 말처럼 보이게 하지 않는다.
- 출처끼리 어긋날 때, 계산한 수치, 열리지 않는 주소, 번역 인용, 인용할 말이 없는 소재는 `references/07-사실-다루기.md`를 따른다.

### 3. 설계 결정 다섯 가지

카드를 쓰기 전에 다섯 가지를 한 줄씩 적는다. 대본 파일의 `meta`에 그대로 들어간다.

1. **갈래**: `references/01-갈래와-비트시트.md`에서 고른다.
2. **축이 되는 사실 하나**: 통념의 핵심 낱말 하나를 건드릴 만큼 작고, 화면에 그대로 보여 줄 수 있는 사실(숫자, 물건, 날짜). 이 사실이 대상을 깎지 않고 더 무겁게 만드는 지점까지 밀고 간다.
3. **마지막 한 줄**: 인용, 질문, 사실 한 줄, 1인칭 선언 가운데 하나. 요약과 당부는 안 된다. 이것을 먼저 정한다.
4. **되받을 것**: 마지막 한 줄이 되받을 낱말, 비유, 장면. 이것을 훅에 심는다.
5. **감출 낱말**: 주제어, 개념어, 주인공 이름 가운데 제목 전까지 쓰지 않을 것(감춤형 훅일 때). 리드형 훅이면 첫 문장에 말할 결과(`meta.lead`). 그림 훅이면 이름 카드 전까지 쓰지 않을 개념의 이름.

### 4. 비트 시트

갈래에 맞는 비트 시트를 `references/01-갈래와-비트시트.md`에서 가져와 시각을 배정한다. 비트마다 "하는 일"을 한 줄로 적는다.

### 5. 분업 정하기

비트마다 두 칸을 채운다. **장면이 말할 것**(`beats[].scene`)과 **문장이 말할 것**(`beats[].text`). 문장 칸에는 찍을 수 없는 것만 남긴다: 원인, 수치, 시간의 길이, 이름, 출처, 논리의 방향, 속마음. 기준은 `references/04-장면-제안.md`.

### 6. 카드 쓰기

`references/02-카드-규격.md`의 규격으로 쓴다. 가장 중요한 다섯 가지만 여기 적는다.

- 카드 한 장은 **2줄, 20~35자, 5~9초**. 5분이면 편집 문장 26~38장, 600~1,000자. 넘쳐도 실패고 모자라도 실패다. 구절마다 카드를 나눠 평균이 15자 아래로 내려가면 조각나 보인다.
- **한 문장을 카드 2~3장에 나누고, 앞 카드는 연결어미나 명사에서 끊는다.** 핵심 낱말과 숫자는 마지막 줄에 혼자 세운다.
- **꺾이는 자리마다 접속어를 단독 카드나 첫 줄에** 둔다.
- 편집 문장은 **사실, 수치, 인과만**. 감정과 평가는 인용에 맡긴다.
- 수치는 **한 카드에 하나**, 비교 짝이나 생활 단위와 함께.
- 날짜, 장소, 직함, 출처는 문장에 섞지 않고 그 카드의 **구석 표기**(`label`)로 뺀다.

훅, 전환, 결말을 쓸 때는 `references/03-훅-전환-결말.md`의 유형표에서 고른다.

### 7. 장면 제안 붙이기

카드마다 장면을 하나씩 제안한다: 유형, 내용, 그 장면이 맡는 정보. 문장 없이 장면만 흐르는 구간(`무문장`)도 카드로 적는다. 소리 큐는 구간이 바뀌는 곳에만 적는다. 기준은 `references/04-장면-제안.md`.

제작 스킬에 넘길 대본이면 같은 문서 9절(제작으로 넘기기 전에)을 따른다. 되풀이되는 대상을 `meta.cast`에, 색과 기호의 뜻을 `meta.visual_code`에 한 번씩 적고, 장면마다 `carries`에 적은 정보가 그 시점과 화면 범위에서 실제로 보이는지 확인한다. 이 절은 90초 대본 한 편을 끝까지 제작해 보고 나온 것이다.

제작본에서 문장이 읽히려면 자리와 모양도 함께 넘겨야 한다. 화면 문장은 모든 카드에서 화면 한가운데 같은 자리에 가는 흰 글씨로 뜨고, 그림은 그 자리를 비운다(`references/02-카드-규격.md` 13절). 음악은 대본이 짓지 않고 `meta.music_brief`로 기준만 넘겨 공개 음원에서 고르게 한다.

### 8. 검수와 가편집 시트

대본을 `references/06-대본-데이터-규격.md`의 JSON으로 저장하고 스크립트를 돌린다.

```
python scripts/build_sheet.py --scripts 대본.json --out 가편집시트.html
python scripts/build_sheet.py --scripts 대본.json --lint-only --verbose
```

- 스크립트가 자동 검수(분량, 속도, 감춤, 전환, 결말, 출처, 제작 인계 등)를 하고 결과를 HTML에 함께 넣는다.
- `실패`가 하나라도 있으면 대본을 고쳐 다시 돌린다. `주의`는 하나씩 읽고 고칠지 그대로 둘지 정한 뒤, 그대로 두는 것은 까닭을 `meta.review_notes`에 적는다.
- 자동 검수가 못 보는 것은 `references/05-검수.md`의 수동 항목으로 직접 본다. 특히 "장면에 보이는 것을 문장이 다시 말하는 카드"는 사람이 봐야 한다.
- HTML을 열어 **가편집 재생으로 끝까지 한 번 읽는다.** 읽다가 숨이 차거나 기다려지지 않는 자리를 고친다. HTML을 열 수 없는 환경이면 `--print-cards`로 카드를 시각 순서대로 뽑아 읽는다(`--out` 없이 써도 된다). Windows PowerShell에서 한글이 깨지면 먼저 `$env:PYTHONIOENCODING = "utf-8"`을 준다. 영어 대본은 `references/02` 11절을 먼저 읽는다.
- **자동 검수가 깨끗하다고 끝난 것이 아니다.** 시험에서 자동 검수를 한 번에 통과한 대본도 수동 검수에서 장면과 문장의 겹침, 낡은 수치, 뺀 사실이 나왔다.

## 산출물

1. `대본.json`: 설계 결정, 비트, 카드(문장, 구분, 시간, 장면 제안, 소리, 출처)
2. `가편집시트.html`: 설계 결정, 가편집 재생, 풀 시트, 검수 결과, 출처를 한 파일에
3. 사용자에게 보내는 짧은 보고: 고른 갈래와 까닭, 축이 되는 사실, 마지막 한 줄, 검수에서 남긴 주의와 그 까닭, 확인하지 못한 사실

## 하지 않는 것

- 내레이션 원고를 쓰지 않는다. 읽어 줄 목소리가 있는 영상이면 이 스킬의 규격(카드당 35자)이 맞지 않는다고 알리고, 화면 문장 판으로 다시 짤지 묻지 말고 화면 문장 판을 제안한다.
- 렌더링, 음악 제작, 이미지 생성을 하지 않는다. 장면은 글로만 제안한다.
- 출처 없는 수치와 인용을 쓰지 않는다.
- 실존 방송의 문장을 그대로 가져다 쓰지 않는다. 참조 문서의 예문은 구조를 보여 주기 위한 것이다.
