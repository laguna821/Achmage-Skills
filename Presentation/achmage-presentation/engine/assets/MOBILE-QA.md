# Mobile deck acceptance
Default <=850px: fit (vertical responsive reflow, one whole slide). Desktop: present (fixed1920 canvas). Explicit selector/query mode survives breakpoints. Read is a separately selected bounded scroll pane. No-JS remains complete document reading.
1. Test every delivered language separately; the matrix checks language coverage, including English when supplied. Use actual DOM slide IDs; never assume s1 versus s01. For light/dark capture every slide in read/present at375x812,768x1024,812x375,1440x1000; fit at375x675,390x664,375x812,768x1024. Wait for ready/fonts. Hash navigation reveals all presentation units; separately test partial/reveal/reset.
2. Evaluate adapters/measure_mobile_layout.js as read-only DOM expression and run node adapters/check_mobile_matrix.js observations.json COUNT LANGUAGES (e.g. ko,en). The checker requires both dimensions, exact ID inventory, nonempty finite geometry, stage within viewport, content/evidence/footer within stage, no chrome overlap, and desktop-normalized presentation geometry.
3. Fit body INCLUDING numeric captions and step numbers must be >=12 effective CSS px in those portrait/tablet sizes with tools/notes closed. This is a minimum screening floor, not proof of comfortable reading. Visually inspect every slide. Never remove content or quietly exempt tiny labels. Long/new content that cannot pass needs authored layout revision before delivery.
4. Verified simple diagram projection retains node text, order, emphasis, every connector and loop endpoints. No arrowhead means no invented direction. Unsupported/ambiguous SVG remains visible but fails fit acceptance until its semantic mobile representation is reviewed.
5. Test default mode, one-page next/previous, 849/850/851, rotation, explicit modes, deep-link reload, 16:10, paired views, modal focus, keyboard, language anchor, notes, tool expansion, chrome hidden, reduced motion, no-JS and print. In read, scroll only between toolbar and controls. Wide-table/diagram local pan must be keyboard focusable, labelled, and tested at both ends.
6. Open menus/notes consume real available space and may shrink the slide below the normal-body floor; test containment and report effective sizes separately. Landscape fit is likewise a separate physical limit, not a portrait readability pass. Native pinch zoom must not be counter-scaled.
7. Preserve original segmented footer, desktop layout, print semantic completeness and Hallym brand. Keep raw failed experiments and current evidence distinct; do not reuse old review hashes after edits.
8. Chromium viewport evidence does not verify physical iPhone, HTML Viewer, dynamic native toolbars, VoiceOver or WebKit. Report these limits. Each future deck must pass the matrix rather than inheriting a blanket pass from the engine.
