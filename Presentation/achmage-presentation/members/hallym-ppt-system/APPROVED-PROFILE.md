# Scoped preservation profile
Read this profile with the newly authored INSTRUCTIONS.md and PATTERN_CATALOG.md. The external development compiler and logo-based templates are not distributed here. Use ../../engine through ../../scripts/presentation.py.

The primary reference is a restrained presentation system: one message per slide, a clear large/small type rhythm, useful whitespace balanced with readable supporting evidence, and a minimal segmented progress footer. A plain appearance is not evidence of weak design. Preserve working details unless a tested alternative improves the actual audience task.

Light: predominantly white canvas; near-black and deep navy text; blue and teal accents. Deep navy/white text belongs in a small emphasis card, not a routine whole-slide dark interlude.
Dark: consistent deep navy canvas and white text; subordinate blue/teal accents. Theme selection is a brand/preference axis, not a quality score. Layout and semantics remain equivalent between themes.
Exact tokens and font files are pinned in ../../engine/brand-tokens.json. No seal, logo or implied university affiliation.

Desktop uses the approved presentation aspect. Mobile fit mode reflows components vertically, then fits one whole slide in the measured space between toolbar and navigation. It must not overlap fixed controls, browser safe areas or the next slide. Read mode is a separate scrolling option. Keep details behind an explicitly labelled disclosure when they support the same message; never hide the sole evidence needed to understand the claim.

Patterns are design vocabulary, not permission to copy fixture facts or force a fixed pattern count into a deck. Choose structure from the message: a denominator flow, a comparison, a time sequence, a single focal number, a trade-off or a decision. Do not add components solely to prove other skills ran.

Any common-engine change follows ../../references/review.md. Mobile geometry and every-slide visual checks apply to new content even when the engine is unchanged.
