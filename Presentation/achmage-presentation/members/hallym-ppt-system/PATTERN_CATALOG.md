# Patterns supported by the pinned engine
This catalog describes the bundle's native schema1 interface and semantic schema2 route. It does not reproduce or promise the external72-template compiler. See ../../references/authoring.md for exact JSON shapes.

| Audience task | Native kind | Composition decision |
|---|---|---|
| Establish a central claim | cover, closing | One focal sentence; a short context line when needed |
| Orient a sequence or transition | divider, steps | Use actual order, not ornamental numbering |
| Compare like-for-like alternatives | schema1 compare; schema2 toggle nodes | Align comparison dimensions; both sides survive PDF/mobile |
| Interpret a small set of quantities | schema1 metrics, bars; schema2 stats nodes | State denominator, units and period; distinguish data from illustration |
| Follow a schedule | timeline | Preserve order and timing semantics |
| Inspect precise values | schema2 table nodes | Keep headers, units and sources; local horizontal pan only when labelled and reachable |
| Explain a relationship | schema2 diagram nodes | Encode the actual relation; verify mobile projection before delivery |
| Present a quotation or focal conclusion | quote | Attribute actual quotations; do not invent a speaker |
| Compose an approved semantic pattern | schemaVersion2 AST | Use allowlisted nodes/roles and real text metrics; no arbitrary scripts or alternate canvas |

Select by the argument, not by visual novelty. A standard comparison may be better than importing a complex corpus widget. New interactive behavior changes the engine contract and needs protected review.

A recognized kind label alone does not construct its contents. Schema1 adapts item fields only for compare, metrics, bars and steps/timeline; it also supports image input and common headline/body/quote content. For toggle, table, diagram, stats, cards or grid use schema2 semantic nodes following the provided example; never assume items automatically render for every recognized kind.
