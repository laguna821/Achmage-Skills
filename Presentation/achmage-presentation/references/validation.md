# Delivery validation
Read engine/assets/MOBILE-QA.md fully. Use allowed browser automation to collect actual DOM measurements with engine/adapters/measure_mobile_layout.js. Use every actual slide ID, all supplied languages, both themes, all three modes and the listed viewports. Wait for fonts and fitting to settle before measurement. Capture screenshots and inspect all slides.
Save raw observations alongside the HTML. Before capture, record SHA256 of every input HTML in a sidecar observations.sources.json; after capture confirm unchanged bytes. The verify command requires this binding and rejects a missing/mismatched binding. Browser observation is evidence, not cryptographic attestation of honest capture.
Use the measurement expression as read-only DOM code. Do not forge values, clear failures, or replay evidence for a changed HTML. The standalone Playwright capture helper may be used only if the host allows it; otherwise follow references/browser-capture.md with CUA.
Typography: test actual glyph bounds, source/footer/control overlap, both dimensions, minimum effective body including numeric captions, and keyboard-accessible local pan. Menus/notes open and landscape fit are reported separately from the normal portrait readability floor.
PDF: inspect text completeness and every rendered page; no public content dropped, no clipped text, notes/control UI excluded, segmented footer preserved. WeasyPrint70.0 is the fixed reference converter. Browser print is a distinct backend needing its own evidence.
Contrast and screenshots remain required under render-audit's applicable layers. Record document-profile scene-check exemptions, not false passes.
Production report: brief/assumptions; title/beat plan; actual six member contributions; input/engine/bundle hashes; HTML/PDF paths; complete observed matrix; visual findings and their resolution; content review; independent review execution if available; explicit not-reviewed list. Never bundle user-private notes with public outputs.
