# 하루 출시 발표 덱: 전달 메모

하루 출시 발표용 덱을 두 개 만들었어요. 하나는 데스크톱(1440 x 900)이고, 하나는 휴대폰 화면용이에요. 둘 다 실제 앱(`?sample=1`)을 그대로 띄우고, 한 단계씩 짚어 가며 보여 줘요.

## 주소

- 데스크톱 덱: https://laguna821.github.io/Achmage-Skills/Product-Design/examples/haru/07-deck/web/
- 휴대폰 덱: https://laguna821.github.io/Achmage-Skills/Product-Design/examples/haru/07-deck/app/

미리보기 서버가 켜져 있어야 열려요. 발표는 1920 x 1080 전체 화면(F)을 기준으로 맞췄어요.

## 키

| 키 | 동작 |
| --- | --- |
| → , Space , PageDown | 다음 단계 |
| ← , PageUp | 이전 단계 |
| L | 라이브 모드. 앱을 직접 눌러 볼 수 있어요. 다시 L을 누르거나 다른 단계로 가면 바꾼 내용은 원래대로 돌아가요. |
| R | 지금 단계를 처음 상태로 다시 만들어요. |
| F | 전체 화면 |
| ? | 도움말 |
| P | 대상 고르기. 덱을 고칠 때만 써요. |

스포트라이트가 비춘 버튼을 직접 눌러도 다음 단계로 넘어가요. 다음 단계의 첫 동작이 같은 클릭일 때만 그래요. 그렇지 않은 곳을 누르면 라이브 모드로 바뀌어요.

## 한 문장 가치

"오늘 할 일만 보이고, 실수는 되돌려요."

## 데스크톱 덱: 13단계

1. 제목 카드: 한 문장 가치
2. 오늘: 오늘 마감과 지난 할 일이 한 목록에 모여요
3. 빠른 추가: "새 할 일" 버튼 (눌러 보세요, 확대 1.7)
4. 빠른 추가: 팝오버에 제목만 적어요 (3단계의 클릭이 첫 동작)
5. 완료: 새 할 일이 들어왔고 동그라미를 눌러요 (눌러 보세요, 확대 2)
6. 완료: 끝낸 일이 "오늘 끝낸 일"로 내려가요
7. 상세: 할 일을 열면 오른쪽에 보여요
8. 삭제: 묻지 않고 지우고 "실행 취소"를 보여 줘요 (확대 1.8)
9. 휴지통: 지운 일이 있고 복원할 수 있어요
10. 프로젝트: 진행도 막대
11. 검색: "회의"를 적으면 할 일과 프로젝트가 한 번에 나와요
12. 라이브: 직접 써 보세요 (오늘 화면에서 시작)
13. 닫는 카드

## 휴대폰 덱: 8단계

1. 제목 카드
2. 탭 바: 오늘, 프로젝트, 검색, 설정
3. 빠른 추가 버튼 (눌러 보세요, 확대 2.2)
4. 빠른 추가 시트: 제목만 적어요
5. 완료: 동그라미를 눌러요 (눌러 보세요, 확대 2.2)
6. 끝낸 일이 아래로 내려가요
7. 실행 취소 메시지: 삭제하면 바로 지우고 되돌릴 수 있어요
8. 닫는 카드

## 확인한 것 (1920 x 1080)

- 두 덱의 모든 단계를 앞으로, 뒤로 넘겨 봤고 "대상을 찾지 못했습니다"는 한 번도 나오지 않았어요.
- 말풍선과 스포트라이트가 겹치는 단계는 없어요. 두 덱 모두 화면에서 측정한 좌표로 확인했어요.
- 화살표 키를 빠르게 여러 번 눌러도 마지막으로 누른 단계에 정확히 도착해요.
- 스포트라이트가 비춘 버튼을 실제 마우스로 눌렀어요. 데스크톱은 3단계와 5단계, 휴대폰은 3단계와 5단계에서 다음 단계로 넘어갔고 앱도 반응했어요.
- L과 R이 동작해요. L에서 바꾼 내용은 나갈 때 사라지고, R은 그 단계를 처음 상태로 되돌려요.
- 뒤로 갈 때 앞 단계 상태가 남아 있지 않은지 앱의 화면 상태로 확인했어요. 아래 "엔진 수정"을 반영한 뒤 모두 깨끗했어요.

## 알아 둘 점

- **엔진 수정(두 deck.js에만 적용).** 뒤로 갈 때 앞 단계 상태가 남는 문제가 있었어요. 원인은 `resetStorage`가 저장소를 비운 뒤에야 이전 페이지가 닫히는데, 이때 앱의 `beforeunload`가 옛 상태를 다시 저장하기 때문이에요. 그래서 새 화면에 열어 두었던 상세와 새 할 일이 되살아났어요. `loadInto`에서 먼저 `about:blank`로 보내 옛 페이지를 닫은 뒤 저장소를 비우도록 고쳤어요. 스킬의 원본 `assets/demo-deck/`는 건드리지 않았어요.
- **샘플 데이터의 순서가 매번 달라요.** 앱이 시드할 때 할 일의 생성 시각에 무작위 값을 더해서, 같은 마감 안에서는 목록 순서가 바뀌어요. 그래서 위치(`:first-child`)가 아니라 체크 버튼의 접근성 이름(`aria-label="‘제목’ 완료"`)으로 할 일을 찾아요.
- **휴대폰 덱은 확대를 두 곳에만 써요.** 폰 화면은 이미 너비가 꽉 차서, 넓은 대상을 확대하면 좌우가 잘려요. 작은 대상(추가 버튼, 동그라미)에만 확대를 써요.

## 스킬과 엔진에서 불분명했던 점

1. **저장소 초기화 순서.** `demo-deck.md`는 `resetStorage: true`면 되돌아가도 깨끗하게 다시 시작한다고 적혀 있어요. 하지만 `beforeunload`에서 저장하는 앱에서는 그렇지 않아요. 위 수정을 스킬에 반영하거나, 이 제약을 문서에 적어야 해요.
2. **클릭이 "같은 클릭"으로 인정되는 범위.** 엔진은 다음 단계의 첫 클릭 대상이 스포트라이트 안에 들어 있으면 다 인정해요. 그래서 시트처럼 넓은 대상을 누르면 가운데를 눌러도 시트 안의 "추가" 클릭으로 간주되어 다음 단계로 넘어가요. 힌트가 있는 단계의 대상은 작은 버튼 하나로 잡아야 해요.
3. **확대 기준.** "관련 글씨가 23px 이상"이라는 규칙은 있지만, 폰 프레임처럼 이미 꽉 찬 대상에서는 확대가 오히려 잘림을 만든다는 설명이 없어요.
4. **목록 순서가 무작위인 앱.** 선택자는 문서에 위치로 고르는 예만 있어요. 텍스트나 접근성 이름으로 고르는 방법(`:has()`와 `aria-label`)을 안내하면 좋아요.
5. **장면 수.** 데스크톱 덱은 13단계라 "약 10단계"보다 많아요. 완료, 빠른 추가를 각각 두 단계로 나눈 결과예요. 줄이려면 6단계(끝낸 일)와 9단계(휴지통)를 합칠 수 있어요.
6. **스크린샷 검증 도구.** 검증하는 동안 브라우저 스크린샷이 가끔 시간 초과로 실패했어요. 재시도하면 되고 덱 자체의 문제는 아니에요.
