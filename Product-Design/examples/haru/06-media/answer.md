# 하루 런칭 자료 전달

런칭 랜딩 페이지와 인스타그램 카드 5장을 만들었어요. 이전 실행이 중간에 끊겨서, 이미 있던 랜딩 페이지, 카드, 스크린샷, 비교 이미지는 그대로 두고 나머지(감사, 대체 텍스트, 근거 노트, 이 답변)를 마무리했어요.

## 파일 (tests\e2e\06-media\)
- `landing\index.html`: 랜딩 페이지. 데스크톱 우선이고 390 px에서도 맞아요. 키트 CSS와 JS, theme.css를 쓰고, 버튼은 하나("하루 시작하기", 링크 `../../04-build/`)예요. 맨 아래에 같은 버튼이 한 번 더 있어요. 화면은 앱에서 직접 찍은 스크린샷(`landing\img\`, 라이트와 다크)이에요.
- `cards\cards.html`: 1080 x 1350 카드 5장(표지, 빠른 추가, 오늘 목록, 프로젝트 진행, 되돌리기와 시작 안내).
- `cards\alt-text.md`: 카드별 대체 텍스트.
- `build-rationale-note.md`: 근거 노트(공예 단계 포함).
- `craft-variants\`: 비교에 쓴 스크린샷.

## 감사 결과 (audit-page.js)
- 랜딩 1280 px 라이트, 다크: 자동 지적 없음.
- 랜딩 390 px 라이트, 다크(터치 대상 44 px 기준): 자동 지적 없음.
- 카드(pxPerPt 2.88, 캔버스 [1080, 1350]): 자동 지적 없음. 캔버스 5개, 캔버스 밖 글자 없음, 안전 여백 침범 없음.
- 이미지 위 글자는 감사기가 못 재는데, 이번에는 사진 위에 놓인 글자가 없어요.

## 비교한 안과 선택
- 랜딩 첫 화면 구성: A 중앙 정렬 헤드라인과 버튼 아래 큰 데스크톱 화면, B 좌우 분할, C 인디고 전체 배경. A를 골랐어요. 헤드라인이 먼저 읽히고, 채워진 색은 버튼 하나뿐이라 "차분하고 또렷함"에 맞아요. B는 화면이 작아져 읽기 어렵고, C는 시끄럽고 버튼이 묻혀요.
- 카드 표지: A 글자만, B 글자와 아래로 잘린 휴대폰, C 인디고 배경과 휴대폰. B를 골랐어요. 첫 장부터 제품이 보이고, 인디고는 시작 안내가 있는 마지막 카드에만 써서 시리즈가 색으로 끝나요.

## 알아 둘 점
- 앱에 없는 기능은 쓰지 않았고, "지금 알아 두면 좋은 점"에 브라우저 저장, 동기화와 알림 없음을 그대로 적었어요.
- 앱이 비어 있어서 샘플 데이터로 찍었어요. 다른 에이전트가 앱을 고치는 중이라 화면이 바뀌면 스크린샷을 다시 찍어야 해요.
- 카드 5의 "프로필 링크에서"는 실제 공개 주소가 정해져야 연결돼요.

## 스킬이 불분명했던 곳
- 웹 랜딩의 디스플레이 헤드라인 상한(Large Title의 2배)은 하우스 규칙으로만 있고 HIG 근거가 없어서, 같은 기준을 카드와 웹에 적용했어요.
- 카드는 앱이 아니라 이미지라 누를 수 없는데 CTA를 버튼 모양으로 둬도 되는지 스킬에 기준이 없었어요.
- 감사기의 터치 대상 기준(390 px는 44, 데스크톱은 28)을 옵션으로 직접 넣어야 하는데, 어느 값을 쓸지 media 가이드에서 한 번에 찾기 어려웠어요.
- 감사기 결과가 "지적 없음"이어도 이미지 위 글자나 의미는 눈으로 봐야 한다는 안내가 있어서 화면을 직접 스크롤하며 확인했어요.
