# Screen spec S08 휴지통 (Trash)

## Identity
- Name: 휴지통 · Medium: web app · Size: compact (pushed from 설정) and regular (sidebar item)
- Job: bring back deleted tasks and projects, or remove them for good. `design-principles/agency/help-people-recover-from-mistakes`

## Content order (most important first)
| Order | Element | Component (decision) | Why here | Rule IDs | Label |
|---|---|---|---|---|---|
| 1 | Deleted items, newest first: type (할 일/프로젝트), title, deleted when, for a project the task count | List | The purpose | `lists-and-tables/best-practices/prefer-displaying-text-in-a-list` | [HIG transfer] |
| 2 | 복원 on each row | Button (plain, on the row) | The main action, per item | `buttons/best-practices/make-buttons-easy-for-people-to` | [HIG transfer] |
| 3 | Row menu: 복원, 영구 삭제 | Context menu (also reachable by a visible "더 보기" button) | Rare action tucked away | `context-menus/best-practices/always-make-context-menu-items-available` | [HIG transfer] |
| 4 | 휴지통 비우기 | Toolbar button, plain, not prominent (D01) | Apart from 복원 | `buttons/role/dont-assign-the-primary-role-to` | [HIG transfer] |
| 5 | Empty state | Text | Explains the place | `writing/best-practices/provide-clear-next-steps-on-any` | [HIG] |

A task whose project is also in the trash is shown inside that project's row, not separately (project restore brings its tasks back together). A task deleted from a live project returns to that project; if the project is gone, to 프로젝트 없음.

## Layout
- **Compact:** pushed screen from 설정 with Back; list full width; 휴지통 비우기 in the toolbar; tab bar visible (under 설정).
- **Regular:** sidebar item 휴지통 at the end; list pane; detail pane shows a read-only preview of the selected item [assumption] or stays empty.
- Spacing multiples of 4 px; targets 44 px / 28 px [House 11]. 복원 and 영구 삭제 are not adjacent without a gap `accessibility/mobility/consider-spacing-between-controls-as-important`.

## Controls and actions
| Control | Action | Prominence | Where | Rule IDs |
|---|---|---|---|---|
| 복원 | Item returns to its place; row leaves; result named in a message "'…'을 되돌렸어요" | Standard | Row trailing | `undo-and-redo/best-practices/show-the-results-of-an-undo` |
| 영구 삭제 (menu) | Confirmation (D01) | Quiet | Row menu | `alerts/buttons/if-theres-a-destructive-action-include` |
| 휴지통 비우기 | Confirmation with count (D01) | Quiet | Toolbar | `feedback/best-practices/warn-people-when-they-initiate-a` |

Restore needs no undo (restore is the undo) per flow-map.

## Data entry
None.

## States
| State | What shows | Rule IDs |
|---|---|---|
| Empty | "휴지통이 비어 있어요. 지운 할 일과 프로젝트가 여기에 와요"; 휴지통 비우기 hidden or disabled with reason | `feedback/best-practices/show-people-when-a-command-cant` |
| Items | List as above; item count in title area | `lists-and-tables/content/keep-item-text-succinct-so-row` |
| Confirming | Action sheet (compact) or alert (regular) (D01) | `action-sheets/best-practices/use-an-action-sheet-not-an` |
| After forever delete | Row leaves; message only states the result, no undo (cannot be undone) | `design-principles/familiarity/provide-clear-feedback` |
| Loading | None | `loading/best-practices/show-something-as-soon-as-possible` |
| Error | Storage banner (D15) | `writing/best-practices/write-clear-error-messages` |

Retention: items stay until emptied by the person; no automatic purge in the first release [assumption] (a purge would delete data without asking).

## Component decisions
D01, D02 (the other side), D15.

## Lenses
**Attention:** the list is the content; restore is the common action and stays more reachable than the destructive ones; no red alarm: destructive style appears only inside the confirmation. **Flow:** reached from 설정 (compact) or sidebar (regular); Back returns to 설정; irreversible steps confirmed (D01) with a safe way out.

## Why-chain
Mistakes are cheap only if recovery exists → Agency → trash as a backstop, confirm only the irreversible → List + confirmation → `design-principles/agency/help-people-recover-from-mistakes` `alerts/best-practices/avoid-displaying-alerts-for-common-undoable` → [HIG]

## Assumptions
- No auto-purge · Why: avoid silent data loss · Confirm with: product owner.
- Compact reaches the trash through 설정 · Why: keeps four tabs `tab-bars/best-practices/avoid-overflow-tabs` · Confirm with: product owner.
