## Layout
- **Compact:** pushed screen. Toolbar (Back, title, 편집, 새 할 일 icon buttons). Header block: gauge, text, then the person filter. Then open tasks, then 완료 N (collapsed). Tab bar stays visible under 프로젝트. Undo message above the tab bar.
- **Regular:** sidebar | list pane (this screen) | detail pane (S04). Header block at the top of the list pane. Toolbar over the list pane. Selected task highlighted.
- Grouping: header block (progress, filter) is one cluster; tasks another, separated by space `layout/visual-hierarchy/group-related-items-to-clearly-express`. Controls spacing: multiples of 4 px, targets 44 px compact and 28 px regular [House 11] `accessibility/mobility/consider-spacing-between-controls-as-important`.
- Long project names wrap in the title area up to two lines at large text; toolbar title is short (the HIG asks for brief titles; names longer than that are cut in the middle with a tooltip on regular) `toolbars/titles/write-a-concise-title` `text-fields/best-practices/consider-using-an-expansion-tooltip-to`.

## Lenses
**Attention:** the project name and gauge are the header; the open tasks are the largest group; one prominent button; secondary controls (filter, 편집) are quiet `buttons/style/in-general-use-a-button-that`; no color coding (D10); done tasks hidden by default `layout/visual-hierarchy/use-progressive-disclosure-to-make-layouts`.
**Flow:** entry from S02 and sidebar; Back goes to S02 with row kept; selecting a task keeps the list highlighted; filter and expansion restore on relaunch `launching/best-practices/restore-the-previous-state-when-your`; delete project is undoable from the message and S08.

### Visual-order method (lenses.md "Reading visual order"). A hypothesis, not measurement
1. **Intended first item:** the project's progress statement ("8개 중 3개 완료") as orientation, then immediately the first open task. The person is here to work, so the tasks must win after one glance at status. `design-principles/purpose/create-value`
2. **Size and weight (for the visual stage):** title largest; progress text one step smaller, Medium weight; filter and secondary text smaller than task titles; task titles at body size. `typography/conveying-hierarchy/adjust-font-weight-size-and-color`
3. **Contrast and color:** the gauge fill and the toolbar button are the only accent areas; the gauge could draw the eye first because it is a colored mass. Conflict noted. Keep the gauge slim and neutral-leaning, so the first task still reads first. `branding/best-practices/apply-your-apps-accent-color-judiciously` `color/liquid-glass-color/apply-color-sparingly-to-the-liquid`
4. **Position and grouping:** top block (title, progress) then filter, then tasks; done list at the end. Status at the top and leading edge. `layout/visual-hierarchy/order-content-by-relative-importance`
5. **Layers:** toolbar over content; tasks are the content layer, no panels behind them. `layout/visual-hierarchy/differentiate-controls-from-content`
6. **Motion:** none required; row settling is optional. `motion/best-practices/make-motion-optional`
7. **Built order:** 1) title and progress text, 2) gauge, 3) 새 할 일 button, 4) first open task rows, 5) filter, 6) done list.
8. **Compare with 1:** close but the button and gauge compete with the first task. Fix by weakening the gauge (slim, no fill glow) and keeping a single accent button; do not enlarge task text. On compact, put the filter after the gauge so it does not push tasks far down. `design-principles/simplicity/establish-hierarchy`
