# Screen spec S02 프로젝트 (Projects list)

## Identity
- Name: 프로젝트 · Medium: web app · Size: compact and regular
- Job: see all projects and how far each one is, and open one. `design-principles/purpose/create-value`
- Container: tab bar item 프로젝트 (compact); sidebar group 프로젝트 (regular). On regular the sidebar already lists each project as the second level, so S02 is the list pane shown when the group itself is selected `sidebars/best-practices/in-general-show-no-more-than`.

## Content order (most important first)
| Order | Element | Component (decision) | Why here | Rule IDs | Label |
|---|---|---|---|---|---|
| 1 | Title "프로젝트" | Toolbar title | Where I am | `toolbars/titles/provide-a-useful-title-for-each` | [HIG transfer] |
| 2 | Project rows: name, gauge + text "8개 중 3개 완료" (D05), open task count is in that text | List (rows) + gauge (D05) | Progress is why projects exist | `feedback/best-practices/consider-integrating-status-feedback-into-your` | [HIG transfer] |
| 3 | Member names on the row, short ("나, 민지" or "3명") | Secondary text | Who is in it, only if short | `lists-and-tables/content/keep-item-text-succinct-so-row` | [HIG transfer] |
| 4 | Toolbar: 새 프로젝트 (plain), 새 할 일 (prominent) | Buttons (D06) | Create actions | `toolbars/actions/use-the-prominent-style-for-key` | [HIG transfer] |
| 5 | Empty state | Text + button | Explains and offers next step | `writing/best-practices/provide-clear-next-steps-on-any` | [HIG] |

Project name only identifies a project (D10). Rows are sorted by name or by last use [assumption: last used first].

## Layout
- **Compact:** full-width rows with 44 px targets; each row ends with a disclosure indicator meaning "opens" (pushed screen, D14). Toolbar shows large title; trailing: two icon buttons (새 프로젝트, 새 할 일), each with an accessible text label `icons/best-practices/provide-alternative-text-labels-for-custom`. Tab bar visible.
- **Regular:** list pane with the same rows; selecting a row selects the project in the sidebar and shows S03 in the list pane position (list pane becomes S03; Back is the sidebar group). Detail pane shows the selected task from S03 if any.
- Grouping by space and dividers; rows aligned on the leading edge `layout/visual-hierarchy/align-elements-to-make-them-easier`. Spacing multiples of 4 px, 12 px around controls [House 11] `accessibility/mobility/consider-spacing-between-controls-as-important`.

## Component decisions
D05 (gauge), D06 (add task), D14 (pushed screen on compact), D02, D10 (name only), D15.

## Lenses
**Attention:** project names lead each row at the leading edge; gauge is a quiet second cue; one prominent button `buttons/style/in-general-use-a-button-that`; no color coding of projects (D10) `color/best-practices/avoid-using-the-same-color-to`; comparison across rows relies on gauge length plus text `typography/conveying-hierarchy/adjust-font-weight-size-and-color`.
**Flow:** back from S03 returns to the same row `design-principles/flexibility/preserve-a-persons-context`; empty state offers the first project; creating a project uses a short sheet with a clear Cancel `modality/best-practices/always-give-people-an-obvious-way`.

## Why-chain
Many projects, wanting to see progress → Purpose → scannable rows with status beside each → List + gauge → `lists-and-tables/best-practices/prefer-displaying-text-in-a-list` `feedback/best-practices/consider-integrating-status-feedback-into-your` → [HIG transfer]

## Assumptions
- Sorted by last used · Why: HIG gives no order; recent work first · Confirm with: product owner.
- Members shown only when 3 names or fewer fit, else a count · Why: row text must stay short · Confirm with: designer next stage.
