# 하루 (Haru) 설계 답변: 결정(Decide)과 구성(Compose) 단계

## 먼저 결론
D01부터 D16까지 모두 정했고, 화면 S01 to S09의 명세를 썼습니다. 한 줄 요약:
- **되돌릴 수 없는 일(D01):** 휴지통 비우기, 영구 삭제, 모든 데이터 지우기, 가져오기로 덮어쓰기만 확인을 받아요. 좁은 화면은 액션 시트(Action sheet), 넓은 화면은 알림창(Alert)이고, 위험 버튼 스타일을 쓰고 기본 버튼은 두지 않아요. `alerts/buttons/if-theres-a-destructive-action-include`
- **삭제(D02):** 확인창 없이 지우고 "실행 취소" 메시지를 줘요. 메시지는 타이머로 사라지지 않고, 휴지통이 받쳐 줘요. `alerts/best-practices/avoid-displaying-alerts-for-common-undoable` `accessibility/cognitive/minimize-use-of-time-boxed-interface`
- **마감일(D03):** 팝업 버튼(오늘, 내일, 다음 주, 없음)과 "날짜 고르기"로 여는 날짜 선택기(Date picker). 시간은 뺐어요.
- **필터(D04):** 전체/진행 중/완료 분할 컨트롤을 뺐어요(완료 섹션이 이미 있어요). 담당자 필터만 팝업 버튼으로 둬요.
- **진행도(D05):** 게이지(Gauge)와 "8개 중 3개 완료" 글자를 함께 보여 줘요.
- **빠른 추가(D06):** 좁은 화면은 시트(Sheet), 넓은 화면은 팝오버(Popover). 툴바의 "새 할 일" 버튼으로 열어요.
- **할 일 열기(D07, D14):** 좁은 화면은 전체 폭 화면으로 들어가고(뒤로 가기 있음), 넓은 화면은 오른쪽 상세 창이에요.
- **선택 컨트롤(D08):** 프로젝트와 담당자는 팝업 버튼, 프로젝트 구성원은 체크 표시 목록이에요.
- **완료 컨트롤(D09):** 동그란 토글형 버튼. 누르면 그 자리에서 체크되고, 화면을 떠날 때 완료 섹션으로 옮겨져요.
- **프로젝트 구분(D10):** 이름만. 색과 아이콘은 뺐어요.
- **순서(D11):** 직접 순서 바꾸기는 첫 출시에서 뺐고, 마감일 순으로 정렬해요.
- **구성원(D12):** 설정 목록에서 바로 추가, 이름 눌러 수정, 삭제는 실행 취소 가능.
- **검색 범위(D13):** 할 일과 프로젝트 전체로 고정하고 입력창 안내문에 적어요. 범위 컨트롤은 없어요.
- **저장 문제(D15):** 알림창 대신 화면 위쪽에 계속 보이는 안내 줄(Banner), 가져오기 실패는 가져오기 버튼 옆 메시지예요.
- **오늘 목록(D16):** 오늘, 지난 할 일, 오늘 끝낸 일(접힘) 순서. 지난 할 일에도 빨간 경고는 쓰지 않고 글자로만 알려요.

## 이번에 계약(1단계)에서 바뀐 것
- 마감 "시간" 삭제, 전체/진행 중/완료 필터 삭제, 직접 순서 바꾸기 삭제, 프로젝트 색·아이콘 삭제, 검색 범위 컨트롤 삭제. 모두 "이게 없으면 무엇이 깨지나"에 답이 없어서 뺐어요. `design-principles/simplicity/include-just-whats-necessary`
- 할 일을 완료할 때 실행 취소 메시지는 쓰지 않아요(자주 하는 일이고 그 자리에서 다시 누르면 돌아가요).
- 빠른 추가 버튼은 오늘, 프로젝트, 프로젝트 상세, 검색 화면에 있어요. 휴지통과 설정에는 없어요.

3. **휴지통 항목을 자동으로 지울까요?** 지금은 자동 삭제 없이 직접 비울 때만 지워요.

## 사용한 가정
- 첫 구성원 "나"를 자동으로 만들고, 이름은 바꿀 수 있지만 삭제할 수는 없어요.
- 가져오기는 하루가 내보낸 JSON 파일만 받고, "합치기"는 같은 항목이면 최근 수정본을 남겨요.
- 사이드바가 자동으로 접히는 너비, 빠른 추가 단축키, URL 구조는 HIG에 없어서 다음 단계와 개발자 확인이 필요해요 [HIG none].
- 목록 정렬: 프로젝트는 최근에 연 순서, 할 일은 마감일 순 [House].
- 문구는 해요체. 화면 이름은 stage 1의 한국어 이름을 그대로 써요.
