# HIG review report: 하루 (Haru), built front end

## Scope
- Artifact: 하루, responsive web app (compact below 744 px, regular from 744 px), `tests/e2e/04-build/`, served at https://laguna821.github.io/Achmage-Skills/Product-Design/examples/haru/04-build/. Reviewed: 2026-11-04. I did not design or build it.
- Deliverables checked: `01-plan` (brief, flow map, screens S01 to S09), `02-design` (decisions D01 to D16, screen specs), `03-system` (visual system note, `theme.css`, state-and-feedback table, copy sheet), `04-build` (code, build rationale note).

## How it was tested
- Tested: every screen (S01 to S04, S07, S08, S09 as routes; S05 and S06 as sheet or popover; confirmations as dialogs) at 390 px and 1280 px, light and dark. Also at 700, 744, 960 px (size-class switch), 320 px and 195 px (200 percent zoom of a phone width). `prefers-contrast: more` and `prefers-reduced-motion: reduce` once each (on S01 at 390 px). Root text size set to 32 px. Keyboard-only core flow (Tab order, `n`, type, Enter, Space, Escape, Delete, Ctrl+Z). Accessibility tree read on every screen.
- Measured: `scripts/audit-page.js` on 8 routes x 2 widths x 2 appearances (32 runs; `minTarget` 44 at 390, 28 at 1280). Contrast ratios computed from the page's computed colors with the same formula as `scripts/contrast.mjs`. Geometry from `getBoundingClientRect`. Dialog contents, focus and button styles read from the DOM. `node scripts/trace.mjs tests/e2e` and `node scripts/find-rules.mjs --check` run.
- Not tested: real VoiceOver or screen readers (only the accessibility tree), real touch input and the iOS keyboard, `prefers-reduced-transparency` (not emulatable here; the CSS rule exists in the kit but the app's own CSS has none), the two-tab case, a real file chooser (import was driven by setting the file input), the browser's native date picker popup (not capturable), Safari and Firefox (Chromium only).

## Severity scale [House]
- **Blocker:** breaks an explicit HIG "don't", a minimum size or contrast, or blocks the task.
- **Major:** works against a principle or platform convention.
- **Minor:** polish. Estimates that rest on unmeasured values would be filed as Major ("Blocker if confirmed"); none of the findings below rely on estimates unless marked.

## Lens order [House]
Value, trust, inclusion, flow, attention, interaction, content, platform.

## Description of what is there (before judging)
Nine screens as contracted. Compact: large-title lists, a floating glass tab bar (오늘, 프로젝트, 검색, 설정), an icon-only filled indigo "+" for 새 할 일, pushed detail screens with Back, a bottom sheet for quick add and project editing, action sheets for confirmations. Regular: sidebar, a 360 px list pane and a 600 px detail pane inside a 1200 px shell; a filled "새 할 일" button; popover quick add; alerts. Data is local (`haru.v1`). The first launch loads sample data (3 projects, 14 tasks, members 민지 and 준호). One accent (indigo), flat white rows, Pretendard Variable, Lucide icons, glass on the tab bar and scrolled navigation bars only.

## Summary
- Counts: **Blocker 1 · Major 3 · Minor 13**
- Strongest points: restraint and calm; D02, D05, D09, D12, D13, D15, D16 implemented as decided; audit finds no text under the floor, no target under size, no unnamed control, no unlabeled field in any of 32 runs; contrast and reduced-motion handling work; copy is consistent 해요체.

## Visual order (S01 and S03, both widths) [hypothesis, not eye tracking]
Method from `lenses.md`, factors only.
- **S01.** Intended first: the first open task of today (the job is "what to do today"). Size and weight: title "오늘" 34 px/700 (26 px at 1280) is far above everything; section headers 17 px/600 (13/700), task titles 17 px/500 (13/500), meta 15 px/400 gray. Color: the only saturated item is the filled indigo "+" / "새 할 일" (`#564ADE`), top right. Position: title top left, button top right, first task about 200 px down at 390 px (y = 160 at 1280). Layers: the glass tab bar sits at the bottom, not competing. Motion: none at rest. Likely order: title, accent button, section header, then tasks. Gap to the intent: the repeated word "오늘" (finding 6) and the 56 px gap before the first task delay the content; the accent button outranks every task. At 1280 the order is the same, plus the sidebar's selected tint at the left.
- **S03.** Intended first: the open tasks of this project, with its progress as context. Order: title 34/700 (26 at 1280), gauge and "6개 중 1개 완료" (15 px gray), members line, the filled add button, the filter pill (tinted, accent text), then tasks. The first task row is an overdue one (sorted by date), shown with its date as text, so the list opens with the most urgent item without alarm color. Conflict: three tinted/accent items (add, 편집, filter pill) in the header zone at 390 px; the filter pill looks like a second primary control. Compare with step 1: acceptable; weaken the pill (plain text button) if people read it as an action.

## Craft pass: does it look finished?
Mostly yes. Calm and clear is carried by one accent, flat rows, three type levels and quiet separators; dark mode and increased contrast (opaque tab bar, black separators) are consistent. What keeps it from finished: the nav-bar smudge (7), the misaligned columns at 1280 (8, 9), the unused detail pane (12), and the toast overlap (14). Ordinary finishing, no redesign.

## What works well
- Restraint: no color for overdue or progress, one accent, the gauge in gray with text beside it `color/inclusive-color/avoid-relying-solely-on-color-to`.
- Undo over confirmation for frequent deletes, with counts and no timer `alerts/best-practices/avoid-displaying-alerts-for-common-undoable` `accessibility/cognitive/minimize-use-of-time-boxed-interface`.
- The accessibility tree: every icon button has a name that includes the item ("‘치과 예약 전화하기’ 더 보기"), checkboxes expose state, dialogs name themselves, tab bar uses `aria-current`, status messages are announced `voiceover/descriptions/provide-alternative-labels-for-all-key`.
- Responsive behavior: size classes switch at 744 px, sidebar overlay below 960 px, no horizontal overflow at 320 px, text follows root size `layout/adaptability/design-a-layout-that-adapts-gracefully`.
- Accessibility settings: reduced motion drops durations to 1 ms; increased contrast makes the tab bar opaque with a border; hover-only controls appear only with a fine pointer and stay reachable by focus and context menu.
- Targets: no control under 44 px at 390 px or 28 px at 1280 px in 32 audit runs.
- Copy: consistent 해요체, results stated (what is lost and how many); the app strings match the copy sheet apart from sample data and one delete-all confirmation.
- Honest data handling: banner wording, export offered first, import validation with a clear reason.

## Accepted exceptions
- Audit "clipped text" on 7 routes (a collapsed inline navbar title, e.g. "프로젝트") is a false positive: the title is hidden by design.
- Audit contrast 2.60:1 (light) and 4.27:1 (dark) on the disabled "추가" in S09: disabled control, house style 9 lists disabled states under the tertiary role. Listed here for the owner; no finding.
