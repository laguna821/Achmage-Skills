# Medium: Desktop web

**Baseline:** macOS, with iPadOS pointer guidance for hover and hit regions. Desktop web has a large display, a keyboard and a pointer as primary input, and long sessions, which matches the Mac profile in [macOS](../platforms/macos.md) (default text 13 pt, default control 28x28 pt) and the pointer rules in [iPadOS](../platforms/ipados.md). Everything here is for websites, web apps and front-end interfaces on PCs. For phones and touch-first pages use the mobile guide. The HIG describes apps, not websites, so most rules arrive as [HIG transfer]. Where a rule names the web, it is marked [HIG].

## Choosing a type scale

Desktop web pages fall on a line between app-like interfaces and reading-oriented pages. The HIG has no web type scale. The choice below is labeled honestly.

- **App-like interfaces (dashboards, editors, admin tools, data tables):** use the macOS scale in [tokens](../tokens.md): body 13, callout 12, subheadline 11, footnote and captions 10, title 3 at 15, title 2 at 17, title 1 at 22, large title 26. [HIG transfer] The Mac is a pointer-and-keyboard desktop platform for long sessions, which matches these pages. Stay at or above the 13 pt default and 10 pt minimum for text. `typography/ensuring-legibility/use-font-sizes-that-most-people`
- **Reading-oriented pages (articles, documentation, marketing copy, long-form):** the iOS scale (body 17, footnote 13, title 1 28, large title 34) may serve. [HIG none] The HIG does not describe long-form reading on a desktop, line length, or page text size. The iOS scale is a candidate only because 17 pt is the larger default, and larger text helps people at varied distances. State this choice to the user and let them decide. `typography/ensuring-legibility/use-font-sizes-that-most-people`
- **Do not mix the two scales on one screen.** Pick one per page type and use one set of weights and sizes for the hierarchy. [HIG transfer] `typography/conveying-hierarchy/adjust-font-weight-size-and-color` `typography/conveying-hierarchy/minimize-the-number-of-typefaces-you`
- Avoid ultralight, thin and light weights. Use Regular, Medium, Semibold or Bold. [HIG transfer] `typography/ensuring-legibility/in-general-avoid-light-font-weights`
- Text stays resizable by the person, not by a fixed scale only. [HIG transfer] `accessibility/vision/support-larger-text-sizes`

## Does not apply

- Dynamic Type, size classes, safe areas and Liquid Glass materials as such. Use their intent (reflow, adaptive layout, clear control and content separation), not the APIs. Keep Liquid Glass out of the content layer in any imitation. `materials/liquid-glass/dont-use-liquid-glass-in-the`
- The Apple menu bar, Dock menu, Window menu and the app menu. A web page has no such system surfaces. Use menu content rules only for menus you draw.
- visionOS depth, spatial layout and immersive rules; tvOS focus and lockups; watchOS and Digital Crown rules.
- Haptics, camera, NFC and similar device features: skip unless the browser exposes them.
- Hover-only access to essential actions. The HIG shows hover as a way to reveal hidden controls, so also keep those controls reachable by keyboard and in a short alternative menu. `pointing-devices/platform-considerations/macos/touch-support-for-hidden-controls/make-essential-hidden-controls-available-in` `accessibility/speech/let-people-use-the-keyboard-alone`

## Ask the user first [HIG none]

- Target browsers, minimum and maximum viewport widths, and breakpoints. The HIG gives no web breakpoints or window sizes. House default: compact below 744 px, regular from 744 px (house-style 11); ask only to change it.
- Page width, column count, grid and gutter values, and line length for body text. House defaults: 720 px reading column, 1200 px app content, 4 px spacing scale (house-style 11).
- Whether the product is an app-like interface or a reading page (decides the type scale above).
- Performance targets, SEO, URL structure, routing and deep-link behavior beyond forward and back.
- Cookie and consent banners, tracking and analytics rules beyond the privacy principles above.
- Whether print, full screen and keyboard shortcut maps are required.
- Responsive behavior on phones. Hand off to the mobile guide.
- Spacing scale beyond the 12 pt and 24 pt control gaps. The HIG gives no general spacing grid. House default: multiples of 4 px (house-style 11).

## House style here [House]

- Font is Pretendard Variable. Use the CSS starter in [tokens](../tokens.md). Desktop app-like scale variables are `--d-*` (macOS). Reading pages may use `--m-*` (iOS) if the user agrees. Weights: Regular 400, Medium 500, Semibold 600, Bold 700, Heavy 800.
- Sizes: 1 pt = 1 CSS px as a starting point. This is an implementation choice, not an HIG rule.
- Pointer controls: default 28 px, minimum 20 px (`--target-pointer`, `--target-pointer-min`). If the page is also used by touch, use 44 px and 28 px (`--target-touch`, `--target-touch-min`). Pad hover areas as in the table above. `accessibility/mobility/offer-sufficiently-sized-controls`
- Contrast: 4.5:1 for text up to 17 pt, 3:1 at 18 pt and above or bold. `accessibility/vision/strive-to-meet-color-contrast-minimum`
- Colors: system color variables from the CSS starter, switching on `prefers-color-scheme` and `prefers-contrast: more`.
- Icons: Lucide, 24 px viewBox, `currentColor`, round caps and joins; stroke width matches the text weight (1.5 for 300, 1.75 for 400, 2 for 500, 2.25 for 600, 2.5 for 700). Size icons in `em` against the text they sit with. Give every icon an accessible label. See [icons](../icons.md). Note the HIG prefers SF Symbols in sidebars and toolbars; the house rule replaces them. `icons/best-practices/maintain-visual-consistency-across-all-interface` `icons/best-practices/in-general-match-the-weights-of` `icons/best-practices/provide-alternative-text-labels-for-custom`
