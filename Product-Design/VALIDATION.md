# 1.0.0 검증 범위

검증일: 2026-11-04 ~ 2026-11-05. Windows, Node.js 26, Chromium 계열 브라우저에서 만들고 시험했습니다. HIG는 2026-11-04에 수집한 판을 기준으로 합니다.

## 확인한 내용

- **자료:** HIG 173쪽에서 규칙 2,341개(지침 2,280, 용어 61)를 뽑았습니다. `scripts/fetch-hig.mjs`로 온라인에서 다시 받아도 같은 규칙 ID 2,341개가 나옵니다.
- **공개 검사:** `check-public --final` 통과. 스킬 165개 문서에서 Apple 원문과 9단어 이상 연속 일치 0, 없는 규칙 ID 0, 깨진 링크 0. 쇼케이스 문서 28개도 같은 검사를 통과했습니다.
- **규칙 ID:** 스킬 문서 164개에 인용된 6,441개가 모두 실제 규칙입니다(`find-rules --check`). 컴포넌트 카드 106장의 구조 검사도 통과했습니다.
- **시나리오 시험:** 시나리오 13개, 스킬 없이 한 비교 3개, 재시험 2개. 인용한 규칙 357개가 모두 실재했습니다. 심어 둔 문제 찾기는 아이폰 스크린샷 검토 8/10(아이콘 버튼 크기와 아이콘 스타일 혼용을 놓침), 접근성 검토 11/11이었습니다. 스킬 없이 한 검토는 약 7/10이었고, 현재 HIG에 없는 기준을 근거로 들기도 했습니다.
- **통합 시험 '하루':** 7단계를 단계마다 다른 에이전트가 이어 갔습니다. 화면 9개와 결정 16개가 코드까지 이어졌고(빈 곳 0), 자동 점검 60회(15개 상태 × 2폭 × 2모드)에서 문제 0. 독립 검토의 Blocker 1, Major 3은 처리했고 Minor 13 가운데 11은 해결, 2는 일부 해결입니다.
- **데모 덱 엔진:** 점 갱신 약 10 ms, 일반 단계 약 62 ms, 동작 단계 약 67 ms, 되돌아가며 다시 재생 약 123 ms. 빠른 연타, 뒤로 가기 시 제품 상태 복원, 직접 조작 판정을 시험했습니다.
- **독립 설치 시험:** 스킬 폴더만 빈 곳에 복사해 스크립트 7개를 실행했습니다: 규칙 검색, ID 검사, 대비 계산, 아이콘 규격(102/102), 미리 보기 서버(응답 200), 추적과 원문 수집 도움말. 스킬 밖의 파일을 참조하지 않습니다.
- **DESIGN.md 템플릿:** `@google/design.md` 0.4.0 lint에서 오류 0, 경고 2. 경고 2개는 다크 모드 채움 버튼의 흰 Bold 글자(3.23:1, 3.43:1)로, HIG 표의 굵은 글자 기준 3:1은 넘지만 lint가 쓰는 4.5:1에는 못 미칩니다. 하우스 결정 10으로 공개한 선택입니다.
- **패키지:** `tools/verify_package.py`가 스킬 폴더, `PACKAGE-MANIFEST.json`, 설치 ZIP의 파일과 SHA-256이 서로 같은지 확인합니다.

## 확인하지 않은 내용

- Safari, Firefox, 실제 iPhone, iPad, Mac, VoiceOver에서는 시험하지 않았습니다. `prefers-reduced-transparency` 대응도 Chromium에서만 확인했습니다.
- 다른 PC에서 Claude Code 플러그인 설치와 자동 선택, Codex의 자동 선택은 아직 확인하지 않았습니다.
- 부품 모음에 달력 선택기가 없어 날짜는 브라우저 기본 입력을 씁니다.
- HIG는 계속 바뀝니다. 새 판에서 규칙이 바뀌면 `fetch-hig.mjs`로 다시 받아 `find-rules --check`로 확인해야 합니다.
- 하우스 결정 12(고정 캔버스의 제목 하나는 가장 큰 글자 스타일의 2배까지)는 HIG에 근거가 없는 하우스 결정이며 재검토 대상입니다.

이번 공개는 검증한 파일의 배포입니다. 새로운 제품에서 나온 결과물의 품질을 보증하지 않습니다. 실제 작업마다 스킬의 검토와 점검 절차를 다시 수행하세요.
